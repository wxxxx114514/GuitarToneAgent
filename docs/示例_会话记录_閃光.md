## 混响层

- **RT60 = 0.47 s**（REVERB Decay=30），四次独立测量：0.47 / 0.47 / 0.46 / 0.47 —— 极稳定
- 衰减非单一指数：0.05–0.15s 为 154 dB/s，0.30–0.50s 降到 80 dB/s（扩散尾）
- 设备往返延迟 **98–104 ms**
- 混响在**时均包络**上只贡献 0.90–1.02 dB（skill 记录 0.47 dB 同级）→ 该指标确实看不见混响

## 本轮新增的设备标定

| 参数 | 实测刻度 | 对照 |
|---|---|---|
| EQ 频段 | 0.1705 dB/单位（σ=1.030 八度） | skill 0.1848 / 设备界面 0.5 |
| AMP Mst | **0.158 dB/单位** | 同上量级 |
| **设备界面显示的 dB** | **0.5 dB/单位 —— UI 假象，差 3 倍** | 不可用于计算 |

**Mst 不是 dB 控制，是线性幅度控制（gain ∝ 数值）**：

| 变化 | 20·log₁₀(比值) 预测 | 实测 |
|---|---|---|
| 55 → 35 | −3.92 dB | −3.15 dB |
| 35 → 15 | −7.37 dB | **−7.02 dB** |

同样 20 单位在 55→35 只掉 3.2 dB，在 35→15 掉 7.0 dB。**不存在固定刻度。**

> ⚠️ **已撤销的错误结论**：曾记录"Mst 在 ~35 以下失效（35→15 降 0.00 dB）"。
> 实际原因极可能是**预设 CSFIXRV3 没有真正加载到设备上**，设备仍停在 CSFIXRV2(Mst=35)，
> 所以两次测量完全相同。**不是设备特性。**
>
> **教训**：预测变化与实测变化严重不符时，第一嫌疑是"预设没加载"，不是"设备非线性"。
> 应在改参数前先确认设备上显示的预设名。

## 踩到的坑

1. **设备界面 dB 是 UI 假象**（差 3 倍）—— 第一次看到 `EQ 全 100` 显示成 +16 dB 时误判为"EQ 炸了"
2. **分轨把混响尾巴掐成精确 −240 dB 全零** —— 吉他/贝斯/人声在歌曲结尾都是全零，而母带还有 −51.7 dB。**分轨里没有混响信息，混响只在母带里**
3. **对齐搜索 ±60 ms 太窄** —— 设备往返延迟 98–250 ms，最佳 lag 撞边界 → 相关系数掉到 0.002
4. **录音窗太短会截掉信号** —— 曾出现信号晚 6 秒、窗口切掉
5. **预设名 9 字符会读不进去** —— `CSFIX2RV2` 违规，改 `CSFIXRV2`
6. **全曲平均 chroma 会把调性抹平** —— 必须按半小节分段再取根音分布（skill 自带 `chords.py` 的做法）

## 结论

- **核心音色层：收敛**，1.5 dB 已是内容差异地板，不是没调好
- **周边层：已标定**，RT60 0.47 s 短 room
- **参考端混响真值不可测** —— 歌曲太密（266s 只有 3 个干净收尾）+ 分轨掐尾 + 母带结尾是淡出
