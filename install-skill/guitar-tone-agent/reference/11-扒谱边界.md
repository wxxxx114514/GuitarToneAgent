## 13. 扒谱 / 分析参考曲的边界（实测）

**目标不是"能照着弹的谱"，是"能弹出一段内容匹配的 DI"。** 两者难度差很远。
13. **描述子/指标必须钉死在代码里**（`songlib.technique_descriptor`），
    文档只指向代码。**同一份实现重写一遍就会漂 1.1~1.7 倍**（§7.2）
13. **配方里每留一个没写明的自由度，就等于给未来的自己埋一次 1.6 倍**
    已知自由度：域（比值/质心可不同域）· 统计量 · 门限 · 频段 · 分母上限 · 窗长 · hop
    **锚点必须带实现版本号**，否则后人无法判断它还有没有效

### 13.1 可靠的

| 项 | 方法 | 实测结果 |
|---|---|---|
| 起音密度 | 自适应阈值谱通量 | 某首 4 分钟曲：2558 个，密集段 10–14 音/秒 |
| 调性 | chroma 汇总 | 主音占比 44%、属音 19% → 判定明确 |
| （前置守卫） | **先看平坦度 `max/mean`** | **实测某首曲只 1.23 → 被抹平了，那份结果是垃圾** |
| 和弦（按乐句） | 逐乐句 chroma + 模板匹配 | 可行，见下 |
| 音区 | 逐音 f0 的中位/分布 | 低把位为主 |

**⚠️ 用"全曲平均 chroma"之前，先看平坦度 `max/mean`。**
实测有一首曲子的平坦度只有 **1.23**——真实音乐不可能这么平，
**说明 12 个音级被抹平了，那份结论无效**。
**判据：< 1.5 就按半小节分段再看**（这是 §13.3 的前置检查）。

### 13.2 不可靠的

**① 逐音扒谱（密集失真 riff 上不可行）**
```
12.9 音/秒 → 每个"音"只有 58 ms
8192 点分析窗 = 186 ms，窗比音还长
→ f0 乱跳（实测 E3/G#2/G2/D2/F2/C3 之间跳）
```
**而且 12.9 音/秒根本不是"一个个音"，是连续击弦。**

**② HPS 的八度错误**
失真信号基本音弱、二次谐波强，谐波积谱会锁到 H2 上。
```
实测：E2（82.4 Hz）被报成 E3（164.7 Hz）——正好是 2 倍
```
**修法**：HPS 之后做次谐波校验——如果 f0/2 的谐波支撑度差不多，说明真基频更低。

**③ 失真强力和弦的大小调判定**
```
chroma 里根音和五度最强，三度音经常被谐波掩盖
实测：66% 判成"大三"，但失真吉他里大部分其实是【没有三度的强力和弦】
→ 这个比例不能当真
```

### 13.3 正确做法：按乐句算和弦

```python
# 逐【半小节】或【1-2 秒】算 chroma，再跟和弦模板余弦匹配
c = librosa.feature.chroma_cqt(y=seg, sr=SR, hop_length=512)
v = c.mean(1); v = v / v.sum()
# 模板：强力和弦(根+五) / 大三(根+五+大三度) / 小三(根+五+小三度)
```

**输出**：和弦进行（去重压缩后看变化点）。

**速度检测要留个心眼**：`librosa.beat.beat_track` 常给出实际值的一半
（实测给 92.3 BPM，实际可能是 184.6）。**这只影响乐句切分的粒度，不影响调性。**

### 13.4 对 DI 指令够用了

```
知道调性 + 主要和弦 + 调弦 + 奏法  →  就能生成"让用户弹什么"的指令
不需要音高、不需要节奏型、不需要指法
```

**实测验证**：照这个粒度生成的指令，用户能照做（见 §9.1）。

> **⚠️ 这里的"够用"指的是【生成给用户的指令】够用，
> 不是指合成 DI 够用** —— 合成 DI 已降级为"仅参考"（见 §7.5 / §8.4③）。
