# 14 · 边界（这个 skill 管到哪、不管到哪）

> ★ 边界的原则一句话：**只考虑我们有的**。
> ★ **与设备的关系**：**§八 讲的就是换设备怎么走**；其余（边界原则 / 不搬过程）不绑设备。

---

## 一、目标

```
★ 走通 = 能把一首歌的吉他音色【复制】出来
★ 本质是复制【参考曲】的音色 -> 目标永远是【参考曲】
★ **DI = 用户弹的那段**（= 目标段 DI）—— **不是参考曲本身**；参考曲（分轨）只用来定目标
★ 判定在最后：跑完一轮闭环，用户听了出反馈
```

## 二、三层判据（从粗到细）

```
外层：13 段时均 WMAE（只管方向，不管细节）
内层：5 指标（哨兵，只在越界时报警）
波形：削顶 / 断 / 爆（事故级）
```

## 四、边界（只考虑我们有的）

```
✔ 只用设备（GE250）内的模块
✗ 不用 TONE CAPTURE（要真音箱采样）
✗ 不用 FX LOOP（边界外）
✗ 不用滤波类（Q-FILTER / HIGH PASS / LOW PASS）—— 与 EQ 重叠，实测净增仅 0.8 个点
★ DELAY / REVERB：参考曲上判不了（见 05-已证伪路线）-> 靠分开录音 + 用户听；本轮 Bypass + N/A
★ 素材：【目标 / 目标段】来自参考曲（用户指定段落）· 【DI】= 用户弹的那段（不是参考曲本身）
★ 录音只录【用户弹的 DI】；【参考曲】永远不送、不录
```

## 五、★ 与旧包（GuitarToneAgent）的关系

```
★★ 旧包【只有工具可用】—— 文档全部不搬。
   · 可用（只复用、不改）：tools\ 的 39 个脚本 + winmm.cs · ffmpeg\ · models\ · presets\ · venv\
   · 不搬（包里的文档）：SKILL.md · reference\（14 份）· docs\
   · 理由：旧包写的是【上一轮的设想】，而且型号还混着
           （它 09 的 EQ 模型是 5-BAND 的，我们用的是 MOOER G）
   · ★ **唯一的例外**（全项目唯一一处引用包内旧文）：07 §二 引用了 reference\09-参数速查与经典配置.md —— **仅作对照**（它的 EQ 模型是 **5-BAND**，不是本项目的 **MOOER G**）
=> 本 skill 的资料全部来自【这一轮实测】（gt-test）。
```

## 八、★ 非 GE250 怎么走

**第一步：判「当前不是 GE250」**

```
型号不同 · 音频端点名不同 · .mo 字段名/范围不同 · Type 名单不同 · 效果链顺序不同
=> ★ 只要有一条不同，就按「新设备」走
```

**第二步：先问一件事（走哪条路）**

```
★ **能加载预设吗？**
     -> 能   = ① 我写文件 -> 用户加载 -> ★ **用户回读屏幕确认**
     -> 不能 = ② 我出【人工表格】-> 用户照表拧 -> ★ **用户回读报数**

=> 两条路【差别只有一处 = 参数怎么送进去】；其余（内部格式 / 靶子 / 误差 / 解算 / 判据 / 停手 / 记录）
   **完全一样** —— 见 16
```

**第三步：照用 / 重做**

| | 内容 |
|---|---|
| **照用** | 13 段划分 · 三层门 · 四张图 · 判据四档来源 · 地板 = 内容差 · 停手 = 离地板 ~0.05 dB · B 组 0~10 与顺序铁律 · 对齐三铁律 · 单模块隔离 · 记录纪律 · **02 §八「怎么建尺子」** · **03「每个数怎么算」** · **16 参数表达** · **17 人机交互** |
| **重做** | 阶段 0 全部（两表 / 端点与 REAMP / 复现工具 -DevicePattern / 发送电平安全区）+ 阶段 1 全部（标定 DI · H7 σ · H4 EQ · H1 AMP · H2 CAB · H3 FXA · H11 时间维 · H5 旁通锚 · H8 削顶）|
| **照常** | 阶段 2 / 3 / 4（只换采样率与端点；判据要按新 σ 重定）|
