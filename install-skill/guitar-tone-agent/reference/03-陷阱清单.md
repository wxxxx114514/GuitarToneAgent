## 3. ⚠️ 陷阱清单（每条都真实踩过，代价以小时计）

### 3.1 PowerShell 的 `-shl` 在 `[byte]` 上会截断

```powershell
[byte]0xFF -shl 8       # = 0        type=Byte   ← 静默归零！
[int][byte]0xFF -shl 8  # = 65280    type=Int32  ← 正确
```

**后果**：24-bit PCM 转换时只剩最低字节，发出去的信号比原信号低 **74 dB**，跟原信号相关系数 0.03。
**症状**：设备收到的是垃圾，用户听到"噪声"而不是拨弦声。
**修法**：所有位移前先 `[int]` 强转。**更好的修法：把转换挪到 Python（§3.2）。**

### 3.2 PowerShell 逐样本循环太慢

57.6 万次迭代（12 秒音频），每次做字节运算 + `Array::Copy`，PowerShell 解释器扛不住 → 命令超时被杀。

**修法**：**Python 做转换写 WAV，PowerShell 只负责播放**（`meas_prep.py` + `reamp2.ps1` 的分工）。

### 3.3 预设 JSON 的 `Merge` 数组**必须正好 294 项**

- 写成 300 → **软件整个文件读不进去**（不报错，就是列表里看不到）
- 空对象 `{}` 要展开成 `{\n    }`
- 文件末尾**必须有换行符**

**验证方法**：拿一个软件自己导出的文件，解析后重新序列化，**必须逐字节相同**。做到这一点再生成新文件。

### 3.4 预设名 `fileInfo.name` ≤ 8 字符，别用下划线

- `EQCAL_100`（9 字符）→ 读不出
- `US CLEAN`（8 字符）、`EQFIX2`（6 字符）→ 正常
- **下划线疑似也有问题**，用纯字母数字最稳（`CAL1`、`FIX4`）

### 3.5 每次测量前必须验证"发出去的 PCM"

**这是最重要的一条纪律。**

```bash
# 转完之后立刻验，跟原 DI 比
原始 DI   峰值 -15.76 dBFS
发出的    峰值 -15.76 dBFS     ← 必须一致
最大逐样本差 0.0000
相关系数     1.000000          ← 必须 ≈ 1.0
```

**相关系数 < 0.99 就停手，别往下走。** 否则你会在垃圾数据上分析一整天。

### 3.6 判断"回环是否通"要用**相关系数**，不是电平

| 现象 | 含义 |
|---|---|
| 相关系数 ≥ 0.3 | 真的回录 |
| 相关系数 < 0.1 | 没回录，录到的只是底噪 |
| 电平 −80 dBFS 但相关系数 0.9 | 信号很弱但真实 |

**强失真信号的相关性天然会降到 0.3 左右——不要因为相关性低就判"回环断开"，先看电平。**

### 3.7 设备断电会重置 reamp 设置；软件显示的状态可能不同步

重新上电后：**在软件里点一下 NORMAL，再点回 REAMP**，强制重新下发。

### 3.8 设备索引会变

输出设备索引在 #0 / #3 / #4 之间跳（因为 Windows 重新枚举）。**永远按名字匹配，不按索引。**

### 3.9 **不要为了压指标而大跳参数**（血的教训）

```
J900R原版 → EQFIX1   参数变化 +13/+29/+12/+19/+16   用户：没提问题
EQFIX1   → EQFIX2   参数变化  −3/ +6/ −6/ −1/ +3   用户：和原版差不多
原版      → FIX3     参数变化  −3/+53/ −8/+31/ +9   用户：有电音 ★
```

**大跳参数会产生听得出、但指标测不出的伪影。**
**约束：每轮每频段变化 ≤ ±20 单位，多轮小步迭代。**

**⚠️ "±20 单位 = ±3.7 dB" 只对 EQ 成立。**
AMP / Volume 类是**线性幅度**：`Mst` 55→35 是 −3.9 dB，
35→15 是 −7.4 dB。**同样 20 单位，低值区能到 7 dB。**（见 §10.5）

### 3.10 JS 模板字符串会吃掉反斜杠

写 PowerShell 路径时用 `String.raw`，否则 `'<包根>\_env\winmm.cs'` 会变成 `'D:project_stemswinmm.cs'`。
同理，**PowerShell 里的反引号别写在 JS 模板字符串里**。

### 3.11 `.ps1` 执行策略

不能直接 `-File` 运行。用：
```powershell
& ([scriptblock]::Create((Get-Content 'xxx.ps1' -Raw -Encoding UTF8)))
```
脚本内容**尽量用 ASCII**，中文在 ANSI 解析下会乱码。

### 3.12 ⚠️ 采样率：stems 是 **44100**，reamp 录音是 **48000**

**这个坑我踩了两次。**

```
BS-Roformer / htdemucs 输出   →  44100 Hz   （跟原曲一致）
reamp 录音（设备回传）        →  48000 Hz   （设备固定）
```

**写错会同时歪掉时间轴和频率轴（8.8%）：**
```
把 44100 的信号按 48000 解释：
  时间标签偏 8.8%     写"10-28s"实际是 10.9-30.5s
  频率标签偏 8.8%     写"30-70Hz"实际是 27.6-64.3Hz
```

**纪律**：读任何音频后立刻 `assert sr == SR`，别信全局常量。

```python
x, sr = sf.read(p, always_2d=True, dtype="float32")
assert sr == SR, "%s 采样率 %d != %d" % (p, sr, SR)
```

### 3.13 ⚠️ `sf.read` 不加 `always_2d=True` 会在立体声上炸

`meas_prep.py` 原来没加，遇到立体声 DI 时 `np.stack` 会产出 3 维数组。
**之前的 DI 都是单声道，所以一直没暴露。** 用 `meas_prep.py`（已修）：

```python
x, sr = sf.read(DI, always_2d=True, dtype="float32")
mono = x.mean(1)            # 立体声 -> 单声道
```

### 3.14 ⚠️ PowerShell 脚本的五条铁律（写工具时必看）

做 `<StemSep 目录>` 独立工具时踩出来的，**代价 8 轮调试**。详见 `<StemSep 目录>\README.md`：

```
① 脚本含中文必须配 UTF-8 BOM（且加 BOM 前先剥掉已有的，否则双 BOM
   的症状跟没加 BOM 一模一样）
② 参数名避开自动变量（$Input / $Args / $Error / $Host / $PWD）
③ 包装原生命令别用 $ErrorActionPreference = 'Stop'
   （python/ffmpeg 往 stderr 打日志是常态，会被当成致命错误 →
     工具"看起来跑完了"但静默失败）
④ Test-Path 处理用户路径必须用 -LiteralPath
   （文件名里的 [ ] 会被当通配符——音乐文件名带方括号太常见）
⑤ 控制台输出中文要 chcp 65001 + PYTHONIOENCODING=utf-8
```

**③ 和 ④ 最贵**——报错信息都指向别处，看不出真正原因。

### 3.15 ⚠️ 分轨会把混响尾巴掐成精确 −240 dB 全零

歌曲结尾实测：

| 轨 | 262 s 时电平 |
|---|---|
| 母带 | −68 dB（还有尾巴） |
| guitar / bass / vocals | **−240 dB（精确全零）** |
| drums | −74 dB |

**含义**：
- **分轨里没有混响信息，混响只存在于母带。** 测参考曲的空间感必须用母带。
- 顺带：**分轨的"静音段"不等于原曲静音段**，别拿它当噪声门限。

### 3.16 ⚠️ 参考曲的混响真值可能根本测不到

实测一首 266 秒的歌：只有 3 个干净收尾点（密度 1.38 音/秒），
三点 RT60 差 **6 倍**（0.24 / 1.47 / 0.67），其中两个尾音中位 **−98 dB**（数字静音）；
母带唯一的干净衰减是整体淡出（259–263 s 稳定 −9 dB/s，264 s 硬切静音），
读出 2.5–6.7 s，**物理不可信**；唯一可信的候选点（215.2 s）**吉他还在弹**。

**第二个会话（266 秒的歌）的完整证据链**：

```
干净收尾点：全曲只有 3 个
三个点 RT60：0.24 / 1.47 / 0.67 s   —— 差 6 倍，不可信
其中两个尾音中位：−98 dB（数字静音，测的是噪声）
母带唯一干净衰减：259–263 s 整体淡出（稳定 −9 dB/s），264 s 硬切静音
   -> 读出 2.5–6.7 s，物理不可信（那是淡出曲线，不是房间）
唯一可信候选点：215.2 s   —— 但吉他还在弹
```

**结论**：周边层没有可优化对照的真值时：
**只标定器件端 + 选一个合理的值，写清楚"这一层是选的，不是测出来的"。**

> **不要为了凑一个 RT60 数字去用淡出段** —— 那会把「工程师的推子」
> 当成「房间的混响」写进结论。**没有真值就说没有。**

### 3.17 ⚠️⚠️ 不要用"读出来再写回去"的方式改文件

> **读工具对长文件有【静默截断】——实测上限 30530 字符。**
> 超出部分不报错、不提示，你会以为读全了。
>
> 本次后果：备份是截断的 → 回写把 §10.3 后半 + §11 + §12 + §13 **全删了**。

**正确做法**：
```
备份      用真正的复制（Copy-Item -LiteralPath / fs.copyFileSync），不要读-写
改文件    定点替换（锚点唯一才动手），不要整文件重写
改完立刻  核对：总行数 / 二级标题数 / 代码围栏是否偶数配平
```

**验证截断确实存在的方法**（本文件实测）：
```
文件  1372 行 / 34091 字符
read  1222 行 / 30530 字符   ← 少了 150 行，静默
```

### 3.18 ⚠️ PowerShell 5.1 的 `Get-Content` 按 CRLF 切行——LF 文件会被当成【一行】

**症状**：配置文件用 LF 换行写入，`Get-Content` 读出来整个文件是一行，
注释和值粘连在一起，然后被 `StartsWith('#')` 之类的过滤条件整条丢掉。
**安静失败**——不报错，只是配置不生效。

实测（`python_path.txt`，4 行 LF）：
```
[1] '# 告诉 tone.ps1 用哪个 Python。 # 优先级：...'      <- 两行粘一起
[2] '# 改这一行即可。<包根>\_env\venv\...'    <- 注释和路径粘一起
                                                       -> 被过滤掉，路径丢失
```

**修法（两条都做）**：

```powershell
# 1) 数据文件用 CRLF 写
'line1','line2' -join "`r`n" | Set-Content -LiteralPath x.txt -Encoding UTF8

# 2) 读的时候自己切，两种换行都兼容
$txt = Get-Content -LiteralPath x.txt -Raw -Encoding UTF8
($txt -split "`r?`n") | ForEach-Object { ... }
```

> **凡是给 PowerShell 读的数据文件（配置、清单、路径表），一律 CRLF。**
> `.ps1` 脚本本身 LF 也能跑（有 BOM 即可），但**数据文件不行**。
