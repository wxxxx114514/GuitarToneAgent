# 17 · 人机交互（怎么把改动告诉用户）

> ★ 目的：让用户**能照做、能回读、能复述**。他不是执行器，是**唯一的感官 + 唯一的物理手**。
> ★ 用户只做三件事：**加载** · **拧旋钮** · **听**。其余全是我的。


> ★ **与设备的关系**：**五句 / 六项 / 改动清单格式 / 只有**四种**情况找用户 = 通用**；
> **走哪条路径（谁回读）绑设备** —— **换设备**先问「**能加载预设吗**」-> 能走 ① · 不能走 ②，见 **16-参数表达规范**。

---

## 一、★★ 五句指令（每步开始前，必须给）

```
① 这一步是什么        （用设备上的话，不上术语）
② 为什么要做它        （一句话原理）
③ 要你做什么          （动作 + 回读确认）
④ 预期看到什么 / 若相反意味着什么
⑤ 这一步不做，会缺什么
```

★ 实测教训（账本 **#139**）：**同一个口径我理解了三轮才对** —— 所以收到指令时
　**先复述方案的设计（开哪些模块 / 动不动参数 / 几版）让用户确认，再动手写预设**。

---

## 二、★★ 改动清单（每轮给用户的，就这一张）

**格式**（见 **16-参数表达规范**）：

```
<模块>.<参数>：<旧> -> <新>
```

**例（本轮实际的一轮）**：

```
AMP.Bass：50 -> 34
AMP.Mid：30 -> 70
（Treble / Pres 不动 —— 理由：B10~B12 已接近，动了会推过头）
```

**配套三样，缺一不可**：

```
① 改动清单（上面那个格式）
② 核对表：点哪个模块 · 屏幕该显示什么
③ 回读要求：加载完请念「预设名 + 上面每个值」
```

---

## 三、★★ 回读确认（B 组步 2）

| 走哪条路（见 16）| 谁来回读 | 回读什么 |
|---|---|---|
| **能加载预设** | **用户** | 屏幕上的**预设名** + 每个改动后的值 |
| **只能手动调** | **用户** | 拧完逐项**报数** |


★ **回读不一致 -> 本次测量作废**，不许解释成「设备非线性」。
★ 为什么这一步值得单列：**H8 那批就是加载错，整批 15 个录音作废**（账本 #225）。

---

## 四、★★ 六项报告（每步做完，我给用户）

```
第 0 项 · 结论   一句话说清「是什么 / 怎么办」（不许用过程量淹没结论）
1 过程量         跑的命令 + 完整原始输出 + 中间量（不截断、不摘录）
2 判据 + 来源    哪条判据 · 来源是 实测 / 换算 / 我定 / ⛔待定
3 结论           通过 / 不通过 / 存疑
4 异常           逐项列（削顶 / lag / corr / 未定项 / **回读不符**）
5 （若有）听什么  A 文件 vs B 文件 + 听什么
6 下一步 + 为什么
```

---

## 五、★★ 只有这四种情况才回去找用户

```
① 需要他做取舍（例如某件事砍不砍）
② ★ 需要他【听分轨】定目标段落 + 声道（阶段 2 步 2.2 / 2.3）
③ 需要他提供东西（录音 / 设备截图 / 和弦表）
④ 需要他【回读确认】（阶段 3 步 2）· 需要他听（阶段 3 步 10 · 步 4 判不了时）
```

★ 用户提供的只有：**设备事实**（名字 / 范围 / 链序 / 字段名）+ **操作** + **耳朵**。
★ **不许把「我该定的」推给用户**（用哪些模块 / 哪个 Type / 步长 / 判据 / 起点候选）。

## 六、★ 反面清单（我犯过的 —— 别再犯）

| 我犯的 | 依据 | 改成 |
|---|---|---|
| 用他不熟的黑话（"存在性""闸"）| 账本 #135 #139 | 大白话（"回读屏幕，确认加载的是我写的那个"）|
