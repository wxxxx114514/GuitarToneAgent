# 16 · 参数表达规范（我们自己定格式 · 送/验两步）

> ★ 最要紧的一条（用户口径）：**预设内容我们自己建一个 JSON**；
> 　设备**能加载预设** -> 我写文件、用户加载；**只能手动调** -> 出【人工表格】让用户照着拧。
> 　「没 json 预设的不是完了」-> **不完**，只是换成手动那条路。


> ★ **与设备的关系**：**两条路都不绑设备**（内部格式是我们自己定的）；「能加载预设吗」的答案随设备变。
---

## 一、★★ 三层分离（谁定什么）

```
我们的内部格式（语义 · 设备无关 · 我们自己定）
         |
    [适配器 —— 每台设备一个：映射表]
       /                        \
  【能加载预设】             【只能手动调】
  我写文件 -> 用户加载        我出【人工表格】-> 用户照表拧
  ★ 用户回读屏幕确认          ★ 用户回读报数
```

| 层 | 定义 | 谁定 |
|---|---|---|
| **内部格式** | **语义**：模块 / 开关 / 类型 / 参数值（+ 每个值的来源）| ★ **我们定**（稳定、通用）|
| **设备库映射表** | 语义名 <-> 设备字段名（amp.bass <-> AMP.Data.Bass）| 每台抄一次 |
| **设备格式** | .mo 的 JSON / 手册的表格 | 设备定 |

★ **换设备 = 换映射表** —— 我们的格式与算法一个字不动。
★ **读和写是两件事**：**读**（从 .mo 抄字段名）可以抄；**写**（生成要给设备的东西）**不许绑死在字段名上**。

---

## 二、★★ 两条路（差别只有一处 = 参数怎么送进去）

| 层 | **① 能加载预设** | **② 只能手动调** |
|---|---|---|
| 内部格式（要什么音色）| **同一份** | **同一份** |
| 靶子 / 误差 / 解算 / 判据 / 停手 / 记录 | **完全一样** | **完全一样** |
| **-> 送参数** | 我写文件 -> **用户加载** | 我出**表** -> **用户照表拧** |
| **-> 验参数** | ★ **用户回读屏幕确认** | ★ **用户回读报数** |
| 录音 / 听 / 判 | 人 | 人 |

★ **分叉只有一处 —— "加载音色"；上下游全部共用。**
★★ **共同点：验参数都是【用户回读】** —— 因为【程序化回读】不在考虑内。
★ 其余（内部格式 / 靶子 / 误差 / 解算 / 判据 / 停手 / 记录）**完全一样**。
★ 所以：**格式比"怎么送"重要得多** —— 格式错了两条路一起错；加载方式只是个插头。

---

## 三、★★ 参数通道里【没有人听】

```
参数通道    送 / 验        <- 纯机械事务，跟听无关（人的角色只有手）
   |
录音        人按一下
   |
算误差      机器
   |
验收 / 停手  <- 这里才可能有人听（另一套东西）
```

★ 两件事别混：
　**参数通道** 管「我要的参数有没有真的进设备」—— 机器 diff 或人工核对，**都不需要听**；
　**验收** 管「像不像」—— 才用耳朵，而且是**单独一层**，不是每个环节都带。

## 四、内部格式的设计要点

| # | 要点 | 为什么 |
|---|---|---|
| 1 | **只放语义**：模块 / 开关 / 类型 / 参数 | 设备无关 |
| 2 | ★ **每个值带来源**：{"value":40,"source":"spec_default / classic / solver / unknown"} | **把"不许编"写进数据结构** —— 谁编的一眼可见 |
| 3 | **未定 = null + 进 unknowns**（不是编一个数）| 同 2 |
| 4 | **设备相关（字段名 / 范围）不进内部格式** | 那些进设备库 |

---

## 五、统一表达（不依赖文件格式）

```
<模块>.<参数>：<旧> -> <新>
```

**例**
```
AMP.Bass：50 -> 34
CAB.Mic：U87 -> SM57          <- 离散项，写档位名
EQ.100Hz：32 -> 30
FXA.Switch：ON -> OFF
```

**约定**
- 一行一条改动；**不写"大概 / 左右"**（要写就写确切值 + 标 ⛔）
- 离散项写**档位名**，括号里带编号：CAB.Mic：U87(2) -> SM57(0)
- **Type 变更单独列**（它不是参数，是模块身份）：AMP.Type：J800(#7) -> ...
- 一条改动要能追到依据：AMP.Bass：50 -> 34（依据：成片映射 · 账本 #210）

---

## 六、★★ 「只能手动调」专属：整轮改动【按模块分组】给

```
一次只给【一个模块区】，组内一次给完，用户拧完 -> 回读 -> 再给下一组：
  AMP -> CAB -> DS/OD -> FXA -> EQ -> NS GATE -> DELAY -> REVERB
理由：这条路没有文件可加载，全靠「我念 + 用户拧 + 用户念」；
     按计算顺序（步3->4->5->6->6b->7->8）跳来跳去给 -> 最容易拧错。
★ 换句话说：**计算按"步"，交付按"模块"。**
```

---

## 七、不管走哪条路，四条共同要求

```
① 每轮只加载 1 次 —— 我算完全部改动 -> 合并 -> 用户【一次】加载（不许改一点加载一次）
② 下完必须【验参数】（B 组步 2）—— ★ **两条路都是【用户回读】**
③ 验参数不一致 -> 【本次测量作废】（不许解释成"设备非线性" —— 账本 #84 的教训）
④ 每条改动都要【记账本】：模块.参数：旧 -> 新 + 依据
```

---

## 八、失效条件（说不出就别用）

| 情况 | 会怎样 | 怎么办 |
|---|---|---|
| 只能导入、不能导出 | 无客观回读 | 步 2 只能靠用户念屏幕；**必须写核对表**（点哪个模块、屏幕该显示什么）|
| 有 JSON 但**格式没写清** | 字段 / 范围 / 加载方式不明 | 先问用户要**格式**（字段 / 范围 / 怎么加载 / 哪些不在 JSON 里）|
