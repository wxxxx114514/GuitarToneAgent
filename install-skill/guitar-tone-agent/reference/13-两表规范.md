# 两表规范（说明书 → parameter_table.json）

> **设备规格只有一个来源：说明书那两页。**
> 这份文档规定它抄成什么格式 —— 抄的是 agent 自己（有模板时，读图填表比写解析器可靠）。

---

## 13.1 两页 → 一个文件

| 说明书上的 | 抄到文件里的哪一块 | 决定什么 |
|---|---|---|
| **模块表**（有哪些模块、各有哪些 Type、链序） | `chain.modules` + `modules.<名>.types` | 起点预设**有哪些模块可开**、Type 编号对不对得上 |
| **参数表**（每个参数的范围 / 步进 / 默认值） | `modules.<名>.params` + `types[].params` | 每个值**拧到几算到顶** |
| 设备导出的一个预设文件（或「没有文件接口」这个事实） | `preset_format` | 生成器**交给谁落地**：文件，还是给用户手动拧的表格 |

三块缺一块都走不下去：缺模块表不知道能开什么；缺参数表解出来的值拧不到；
缺落盘形状就不知道产物是文件还是表格。

---

## 13.2 放哪、谁填

```
devices\<型号>\parameter_table.json         <- 填好的规格（运行时输入，一台设备一份）
reference\parameter_table.template.json     <- 模板（别改它，拷出去填）
```

填表的是 **agent**：读说明书截图 / 设备界面截图，按模板的形状填。填完跑校验，通过才许往下走。

---

## 13.3 字段

| 字段 | 写什么 |
|---|---|
| `schema` | 固定 `parameter_table/v2` |
| `device` / `source` / `confidence` / `updated` | 品牌型号、抄自哪一页、可信度（说明书抄 = high，界面截图猜 = medium）、日期 |
| `chain.modules` | 信号顺序，输入 → 输出。设备允许用户改链序时 `fixed: false` |
| `modules.<名>.file_key` | 这个模块在预设文件 / 设备上的键名，**逐字一致** |
| `modules.<名>.switch_key` | 旁通开关的字段名；不能旁通的模块写 `null` |
| `modules.<名>.type_key` | Type 字段名；没有 Type 的模块写 `null` |
| `modules.<名>.data_key` | 参数容器的字段名；参数直接铺在模块下就写 `null` |
| `modules.<名>.param_order` | 设备界面上的参数顺序（省略 = 用 `params` 的书写顺序） |
| `modules.<名>.types[]` | **模块表**。`id` 从 0 起；`manual_item` = 说明书第几项（1 起），留着自己核对 |
| `modules.<名>.params` | **参数表**：模块级公共参数，大多数 Type 共用 |
| `preset_format.kind` | `json`（能生成预设文件）/ `manual`（只能出表格给人拧） |
| `preset_format.chain_key` / `chain_value` | 链序数组的字段名；数组里放 `module_file_key` 还是 `module_index`（= 在 `chain.modules` 里的下标） |
| `preset_format.template` | 一个**空壳预设**：结构完整、值留空。落盘器按它填 |
| `unknowns` | 所有「说明书没写 / 看不清」的条目。生成器原样带出去，不猜 |

---

## 13.4 一个参数怎么写

```json
"Gain": { "range": [0, 100], "step": 1, "default": 50, "unit": "", "note": "" }
"Mic":  { "values": [0, 1, 2], "default": 1 }
```

| 键 | 说明 |
|---|---|
| `range` / `values` | **二选一**。连续量用 `range`，离散量（开关、麦克风型号）用 `values` |
| `step` | 步进。连续量 0.1，整数档 1 |
| `default` | 说明书给的默认值。**说明书没写就省略这一项，不要填 0 充数** |
| `unit` | 单位。说明书只给档位时写「档」 |
| `note` | 会让人拧错的坑，例如「线性幅度，不是 dB」「界面显示值是实际值的 1/3」 |

---

## 13.5 六个容易填错的地方

| 坑 | 怎么填才对 | 填错的后果 |
|---|---|---|
| **Type 编号** | 说明书第 1 项 = `id` 0；`manual_item` 留着核对 | 生成器落到别的 Type 上，那个 Type 的键名可能完全不同 |
| **参数挂模块还是挂 Type** | 大多数 Type 共用 → 模块级 `params`；某个 Type 键名不同 → 该 Type 写 `params_from_module: false` + 自己的 `params` | EQ 这类「换个 Type 键名全变」的模块会带着上一个 Type 的键 |
| **键名逐字** | `file_key` / `switch_key` / `type_key` / `data_key` 与预设文件逐字一致 | 落盘器写出来的文件设备读不了 |
| **`range` 照抄** | 有的设备是 −12~+12 dB，有的是 0–10 档 | 夹紧值算错，报「到顶了」的位置也错 |
| **看不清就省略** | 写进 `unknowns` | 猜出来的参数会让用户拧到错位置 |
| **链序** | `chain.modules` 写信号顺序（输入→输出） | 落盘出来的 effectChain 是错的链序 |

## 13.6 填表流程（4 步，每步有产物）

**① 拷模板**

```powershell
New-Item -ItemType Directory -Force -Path devices\<型号> | Out-Null
Copy-Item reference\parameter_table.template.json devices\<型号>\parameter_table.json
```

**② 读说明书填** —— 照模板里 `_示例` 的形状；`_` 开头的键是说明，程序会忽略。

**③ 校验**

```powershell
tone.bat run check_parameter_table.py devices\<型号>\parameter_table.json --table
```

产物 = **通过 / 不通过**（不通过会指到具体字段）+ **给人看的设备规格表**。
那张表就是 guitar-tone-manual 第三步要交给用户确认的东西。

**④ 让用户在设备上回读 Type 名** —— 编号错位校验器抓不到（它只能查表内自洽），
只能靠屏幕回读（SKILL.md 铁律 3）。

---

## 13.7 缺了怎么办（三档）

| 缺什么 | 怎么办 |
|---|---|
| **整表没有** | 不开工（SKILL.md ⓪）。没有它，起点预设只能靠现成预设改 —— 那是修正，不是生成 |
| **某模块 / 某 Type 的参数看不清** | 省略 + 进 `unknowns`。生成器按「说明书默认值 → 范围中点」兜底，并把兜底的那几条列进**未定项**，不混进正常值里 |
| **设备没有预设文件接口** | `preset_format.kind = "manual"`。生成器不出文件，出「拧到几」的表，用户手动拧（guitar-tone-manual） |

---

## 13.8 失效条件（这表管什么、不管什么）

| 它管 | 它不管 |
|---|---|
| 结构完整（模块齐、开关明确、链序对） | **音色**。音色判据一律是残差（§10.7.5） |
| 值拧得到 / 拧不到（`range` 夹紧） | 值**对不对** —— 那是闭环测出来的 |
| Type 编号在表内自洽 | 编号**和真机一致** —— 靠用户回读屏幕 |

- **说明书只给档位（1–10）没给物理量时**：`range` 只能是档位、`unit` 写「档」。
  EQ 的 dB/单位要**标定**（guitar-tone-manual 第四步），不要从说明书推。
- **换固件 / 加装模块** → 表要重新要一次（第零步）。
- **同一型号不同固件的 Type 编号可能不同** → `confidence` 写 medium，并让用户回读。

---

## 13.9 表填好之后

```powershell
tone.bat run synth_start.py <曲风> --device=<型号>
```

`<曲风>` 要写内置的那几个标签之一（`metal` / `anisong` / `hard-rock` / `blues` / `chime` 一族）；
认不出来时脚本会把可用的列出来，不猜。

产物 `<歌曲目录>\start_preset.json`：**只开 AMP + CAB + 推子**，其余模块显式关；
每个值都带【依据】，兜底的进【未定项】—— 字段含义见 `synth_start.py` 的表头。

---

## 13.10 落盘三条（真机导出的预设实测得来，**改落盘器之前先读这三条**）

| 条 | 实测依据 | 怎么做 |
|---|---|---|
| **① 链序不自编** | 两份真机导出文件的 `effectChain` **首元素分别是 4 和 0**（Neko RG vs 包里的历史文件）—— 我们推不出设备用的下标空间 | **原样保留外壳里的链序数组**；只有外壳里根本没有这个字段时才按 `chain.modules` 生成，并进【未定项】让用户回读 |
| **② 关闭的模块也要填 Data** | 设备自己导出的文件里，`Switch=0` 的模块（DELAY / EQ / FXA…）**照样带完整参数** | 关闭模块的 `Data` 填**说明书默认值**（没有默认值就填范围中点并记入未定项）；**不许填空对象** |
| **③ 逐模块判定能不能落盘** | 同一模块换 Type 键名会完全不同（`EQ Type 0` 六个键 vs `EQ Type 3` 九个键，只重叠一个 `Level`） | 表里**记录了这个 Type 的参数**才自动写文件（落盘器判的是「参数集非空」；键名对不对得上由 `check_parameter_table.py` 在**表**这一侧保证，落盘器不重复查）；没记录就**不落盘**：保留外壳里该模块的 Data、出一行人工表 —— 这就是「其他的东西变了就变成人工调整机器」的落点 |

**另外两条已经踩过的**：

- **Type 编号的合法来源只有两个**：设备自己导出的预设文件，或说明书上明确写着「第 N 项 = 编号 M」的对照。
  从「说明书第几项 − 1」自己推的一律不算（整表偏 1 的话，换个模块就会加载到隔壁那个型号）。
- **`type_key` 允许「这个模块根本没有 Type 字段」**：实测 FX LOOP 只有 `Data` + `Switch`，没有 `Type`。
  表里写 `null`，落盘器就别给它编一个。

每个值带依据 —— **只有四档，没有「抄现成预设」这一档**：`doctrine`（经典配置，推子那类）/ 
`manual_default`（说明书默认值）/ `range_midpoint`（范围中点，进未定项）/ `values_first`（离散量取第一个，进未定项），
兜底的进**未定项**。然后按 §10.8 的 7 步逐个开模块。
