# 10 · 陷阱清单（上机调音的坑）

> ★ 只收【直接影响「调出音色」正确性】的坑。
> 环境 / 编码 / 文件管理类的坑（引号坑、变量名冲突、归档 read+write 丢行、装环境、PDF 解析）**不收**。
> 每条给：**现象 · 原因 · 修法**。来源：账本 readings.md · _非测试问题.md · 06_坑与修法 A 类。


> ★ **与设备的关系**：坑 1 / 2 / 3 / 11 / 12 **绑设备**（换设备照用，但要重设）；三条对齐铁律与记录纪律 **通用**。

## 一、坑 1~10（上机流程）

### 坑 1 · 加载错了，数据全废

| | |
|---|---|
| **现象** | 整批录音的数值都对不上、符号不对、结论荒唐；回头才发现加载的是另一批预设 |
| **原因** | 两批预设名只差前缀，按序号切就切错 |
| **修法** | ① 设备文件名要能区分批次 ② **每点配「核对表」** ③ 每点录完**立刻验符号 / 位置** |
| **本轮实例** | H8 那批 15 个 wetL* 全废（用户说加载错了）-> calibration.json 标 VALID=false（账本 #225）|
| | 旧批 H4（第一版 13 点）同样作废（账本 #126 #130）|

### 坑 2 · 设备上不是那个预设（界面 != 状态）

| | |
|---|---|
| **现象** | 以为设备上是 A 预设，其实不是 |
| **原因** | 浏览某个模块时**界面会点亮它** -> 界面 != 实际状态 |
| **修法** | 状态一律以**导出的预设文件**为准；取不到就**让用户回读屏幕** |

### 坑 3 · REAMP 模式没开 -> 录回来 ≈ 送出

| | |
|---|---|
| **现象** | 录回来的几乎等于送出的干音；会被误判成「设备无效果」|
| **原因** | AUDIO MODE 是 NORMAL（回传收不到效果链输出）|
| **修法** | 每次上机确认 **AUDIO MODE = REAMP**；断电会重置；若已是 REAMP，点一下 NORMAL 再点回 REAMP 强制下发 |

### 坑 4 · 比「13 段 / 动态」跨了素材

| | |
|---|---|
| **现象** | 同一预设，动态一会儿 21.56 一会儿 0.53；残差一会儿 13.47 一会儿 4.89 |
| **原因** | 一边送的是「第一段 DI」，一边的目标是「目标段」|
| **修法** | ★ **比什么都要同素材**：目标用目标段，就用目标段的湿声 |
| **实证** | 送第一段 DI 动态 21.56 · 送目标段 DI 0.53（差 21 dB）· 账本 #178 #179 |

### 坑 5 · 追「内容差」的段

| | |
|---|---|
| **现象** | 某段怎么调都追不上；硬追会把解出来的参数拉爆 |
| **原因** | 源头 DI 本来就差（B2 多 22 dB、B13 少 23 dB）—— **设备改不了演奏 / 拾音器** |
| **修法** | 先判「是音色差还是内容差」（看源头 DI 的 13 段）-> 内容差段**不追** |
| **实证** | 账本 #194 #195 |

### 坑 6 · 用最小二乘解执行器参数 -> 荒谬值

| | |
|---|---|
| **现象** | 解出 +778 / −1164 值单位（远超值域）|
| **原因** | ① 方向解反了 ② 没剔内容差段 ③ 步 6 本就不该解方程组 |
| **修法** | 步 6 用**成片映射**（Bass 管 B1~B4 / Mid 管 B5~B8 / Treble 管 B10~B13 / Pres 管 B12~B13）|
| **实证** | 账本 #174 #210 |

### 坑 7 · 解算顺序乱（提前用 EQ）

| | |
|---|---|
| **现象** | 越调越差；每轮只赚 0.0x dB |
| **原因** | 顺序铁律是【计算顺序】：1 最前 · 2 是门 · **4 在 8 前** · **7 在 8 前** |
| **修法** | 严格按 **步3 -> 步4 -> 步5 -> 步6 -> 步6b -> 步7 -> 步8** 算 |
| **为什么** | 时基未锁不许解 EQ（混响污染 3.65~8 dB）；先窄后宽（反着只能修 52%，正着 99%）|

### 坑 8 · 以为 DS/OD Volume（Level）是纯电平

| | |
|---|---|
| **现象** | 拿它补响度，结果**音色形状也变了** |
| **原因** | 它是**推子**：推动箱头 -> 失真变 -> 形状变 |
| **实证** | 30->10：电平 −2.60 dB，但 13 段形状变化 RMS **0.998 dB**（账本 #175）|
| **修法** | 响度优先用**回录侧音量**（音色链之外）；音色链里的旋钮只用来调音色 |

### 坑 9 · 窄坑硬修

| | |
|---|---|
| **现象** | 花很多力气修一个「坑」，WMAE 就是不动 |
| **原因** | 滤波类不用（与 EQ 重叠）· AMP 修窄只有 18% · EQ 只有 19% |
| **修法** | 先量「窄坑贡献多少 dB」（平滑前后 WMAE 差）；**< 0.5 dB 就无视** |
| **实证** | 本轮 0.43 dB -> 直接跳过步 7（账本 #185）|

### 坑 10 · 拿外部 AI 给的结构当流程

| | |
|---|---|
| **现象** | 流程照着外来的文档跑，数字对不上、步骤多余 |
| **原因** | 那种文档数字多半是编的、结构是外部给的 |
| **修法** | 我们的流程 = **B 组 步 0~10**；外部文档只看「对照」价值 |
| **实证** | 我拿 执行总装顺序_已审.md（它自己写着「外部AI结构 · 仅作对照」）当顺序 · 见 15 §4.1 |

## 二、★ 坑 11~12（设备库的**转述坑** —— 实打实会写错预设）

### 坑 11 · ★★ 设备库里的字段名是错的（照着写预设会错）

| | |
|---|---|
| **现象** | 照着设备库（mapping.json / parameter_table.json）写预设，字段名对不上 |
| **原因** | mapping.json 是**设计期**写的 —— 那时以为 FXA 是「滤波参量带」，所以它的 FXA / NS GATE 两行是**残留** |
| **实证（逐字段核对真机预设 presetB.mo）** | **FXA** 真实 Data = Attack / Level / Ratio / Thres（**不是** Level / Peak / Position / Q）· **NS GATE** 真实 Data = Attack / Release / Thres（**不是**只有 Thres）|
| **其余模块** | AMP / CAB / DS-OD / EQ / DELAY / REVERB / FXB / FX LOOP / TONE CAP **全部一致** ✓ |
| **修法** | ★ **字段名一律以真机导出的 .mo 为准**（权威顺序：预设文件 > 截图 > 手册 > 我抽的）|

### 坑 12 · ★ parameter_table.json 是**手册草案**，不是参数表

| | |
|---|---|
| **现象** | 把 parameter_table.json 当成「这台设备的参数表」用 -> 拿到一堆「待确认」 |
| **成因** | 它是我从**手册 PDF 抽**的草案（带 PDF 页码、ask 标记、范围多为「待确认」）|
| **手册本身也会错** | Distance 曾被抽成 DISTENCE（账本 #99）· Type 名单被截断 / 漏（账本 #11 #40）|
| **修法** | ① **真值以真机预设为准** ② 手册只作对照 ③ 缺失的字段 -> 记进「未定项」，**不许静默挑一个** |

## 三、★ 三条对齐铁律（我错了三次）

```
① 对齐用【有辨识度段的全范围 FFT 互相关】
   —— 不能假设从 0 开始、不能用 min(len) 截断
② 估增益用【RMS 比】
   —— 逐点最小二乘在微小错位时会崩（实测给过 −28.76 dB）
③ 同一次播放/录音的不同设置版本 -> 必须用【同一个对齐偏移】
   ✗ 每个版本分别对齐 -> 相减时相位对不上（corr 0.025）
   ✓ 统一 lag          -> corr 升到 0.70
```

## 四、问题分三类来结（别混）

| 类 | 是什么 | 怎么算「结」 |

| **A 真问题** | 测试 / 方法 / 工具真的有毛病 | 修好 + 有验证（数字或结论）|
| **B 我的操作错** | 我做错了（加载错 / 算错 / 越权 / 顺序乱）| **不需要「修」** —— 改成习惯 / 铁律即结 |

## 五、记录纪律（三条）

```
① 数值不许写死：有依据的写来源（实测 / 换算 / 我定），没依据的留空标 ⛔
② 每条三件齐全：值（原值 + 单位）· 判据（含来源）· 结论
③ 坑要记全：现象 -> 原因 -> 修法 -> 复发次数
```

**归档机制纪律**

```
★ 纯追加：写归档绝不用 read+write（会丢行）；改前留 .bak；写完跑自检
★ 归档自检要查三件：标题唯一 / 列数一致 / 有数据行（带退出码）
★ 发现缺号要查（本轮靠自检两次抓出缺号）
★ 过程量必须落盘（step_XX_raw / _calc），不许只打在对话里
```

```
上机前：REAMP 开了吗、文件名能区分吗、核对表写了吗、字段名核过真机预设吗。

上机后：同素材比、纯追加记、跑自检。
```
