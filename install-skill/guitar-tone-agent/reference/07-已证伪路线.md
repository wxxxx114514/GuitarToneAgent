## 8. 已证伪的路线（别再试）

### ❌ 8.1 去混响（dereverb）

**四个独立模型，四种架构，全部让频谱更差：**

| 模型 | 频谱偏移 | vs 未处理 | 备注 |
|---|---|---|---|
| 未处理（只有混响） | **0.45 dB** | — | 病很轻 |
| Reverb_HQ_By_FoxJoy | 1.55 | +1.10 | |
| UVR-DeEcho-DeReverb | 1.55 | +1.10 | |
| UVR-De-Echo-Aggressive | 1.59 | +1.14 | 硬门限（动态范围 177 dB） |
| UVR-De-Reverb-aufr33 | 1.61 | +1.16 | 同上 |

**真机混响重测（排除"合成混响不真实"的质疑）：**
```
真值：干声  |  输入：干声 + 真机混响  |  未处理偏移 0.47 dB
dereverb 输出 vs 干声：1.24 / 1.25 dB   → 还是更差
```

**操作性判据（最直接）：**
```
我们的输出  vs 带混响参考    vs 去混响参考
  0.85              1.54        ← 去掉混响反而差 81%
```

**原因**：混响对频谱包络的影响只有 0.47 dB，而 dereverb 会砍掉 **95 Hz 附近 4 dB**——那是闷音的低频冲击，**是音色本身不是混响**。

### ❌ 8.2 用包络自相关测延迟

```
我的链路【完全没有 delay】，自相关却在 250/500/750/1000 ms 出峰
→ 那是干声的 250ms 扫弦节奏
```

**节奏本身产生周期峰，把真实延迟盖掉。**
**修法**：用**延音段**（无节奏）+ **波形相似性**（延迟重复是同一段波形副本，没有新起音瞬态）。

### ❌ 8.3 用传递函数相位/群延迟分析抓伪影

失真信号的相位行为会淹没 EQ 的相位效应（实测算出 70–80 ms 的群延迟σ，物理上不可能）。
**修法**：用**逐帧对齐的 lag**（整体延迟），它不受失真影响——实测干净地抓出了 FIX3 的 6.19 ms。

### ⚠️ 8.4 未决问题（已部分解答，2026-09-28）

**原问题**：FIX3 的"电音"到底是 EQ 的问题，还是**合成 DI × EQ 的交互**造成的？

**现在知道的部分**：

**① 内容不匹配确实会把误差放大 2–3 倍**
```
同一个预设 EQFIX2，同一个全曲目标：
  开放音阶 + C 和弦（内容不匹配）  →  3.87 dB
  E/B 强力和弦闷音（内容匹配）      →  1.60 dB
```
所以**"频谱指标和听感不一致"很可能有一部分就是内容不匹配造成的假误差**。

**② 合成 DI 会过拟合**
```
FIX4（用合成 F# 调 DI + 闷音窗目标调出来的）：
  训练场景（闷音）    改善 0.57 dB
  场景外（开放音阶）  变差 0.55–0.80 dB
```
**净负。** 用合成 DI 可以，但**目标必须是全曲**（§7.4），不能是闷音窗。

**③ 合成 DI = 管线验证夹具，不是音色参考**

它的价值是「让闭环在用户录音前就能跑起来」：验证发送 / 对齐 / 削顶 / 格式 / 解算 / 握手。
**它的误差推不出上界**（参考曲是湿声，结构不同，比不了）——
**推不出上界的误差不能进优化循环。**
用真 DI 定案时**必须回基准预设重新解算**（见 §9.1）。
**仍然未决**：FIX3 的"电音"到底是不是纯 EQ 问题。
**判定方法**（还没做）：把 EQFIX2 和 FIX3 用**同一个内容匹配的 DI** 各渲一遍，
对比逐帧指标（LSD / MCD / lag）。如果 FIX3 在这些指标上正常，
说明"电音"不是频谱层面的问题。

### ❌ 8.5 用「低频占比 + 频谱质心」判奏法

**这两个量测的是音区高低和混音 EQ，不是奏法。**

受控实验（合成信号，**同一个包络**，只改音区）：

| 信号 | 低频占比 | 质心 | 被旧判据判为 |
|---|---|---|---|
| E2 开放（T60 = 1.5 s） | 50.1% | 352 Hz | 闷音 |
| E2 闷音（T60 = 0.15 s） | 50.2% | 355 Hz | 闷音 |
| E4 开放（T60 = 1.5 s） | 20.6% | 1396 Hz | 中间 |
| E4 闷音（T60 = 0.15 s） | 20.7% | 1397 Hz | 中间 |

**衰减时间改 10 倍，判据只动 0.1 个百分点；音区变一个八度，它动 2.4 倍。**

**现场翻车**：温度差报出「闷音 49.1%」，而那首歌一点不闷。
另外阈值 22% 正好压在中位数 21.9% 上 —— 必然切出 49.6%；
分布还是**单峰无二态**（根本没有"闷音群体"和"开放群体"两坨），
质心那一格 93.4% 全通过 = 完全不起作用。

**原因**：弹得低（F2/G2 那些音）100–450 Hz 占比自然就高；混音砍了低频占比就低；
贝斯漏进吉他轨占比也高。**闷音与否它看不见。**

**修法**：判据换成**音符衰减**（`songlib.note_decay_times()`），见 `06-奏法处理.md` §7.1。

### ❌ 8.6 拿 f0 估计器的输出直接当「这个音被弹了」

**两端都错，而且方向相反：**

```
强力和弦 D2+A2+D3（谐波 2:3:4）-> pyin 报 D1（低一个八度，实测 99.8%）
三和弦   F3+A3+C4（谐波 4:5:6）-> pyin 报 F1（低两个八度）
白噪声 / 50 Hz 工频            -> 照样报得出「音」（工频报 G1，占 69% 的帧）
```

**后果**：整首都是强力和弦的 Drop D 曲子被判「全是物理不可能的音 → 测不出调弦」，
而那是**最典型**的 Drop D riff；反过来，噪声会被当成低音证据进入统计。

**修法**：报出的音必须在频谱上真的有分量才算数 ——
没有分量、而它的 2/4/8 倍有，就取「有分量的最小倍数」（`songlib.f0_track`）。
只检查 2 倍不够（三和弦差两个八度）；只比「峰/底噪」也不够（两个都很小的数也能比出 20 dB）。

**这个坑最阴的地方：它从不报错。** 数字看着完全合理，只是把音区当成了奏法。
连带后果是 `verify_di.py` 会一直催用户"再闷紧一点" —— 
被判成闷音的那一段本来就不是闷音，怎么弹都达不到它要的差异。

## 8.7 【已证伪】用「段间一致性」判复数音色（2026-10）

**曾经的设想**：一首歌里两段音色不同时，全曲平均 = 「两种音色的平均值」，
而 `target_whole.py` 已经在打印每 20 秒与全曲平均的偏差 —— 那就在它上面加个阈值，
判出「复数音色」并提醒用户。

**证伪它的反例（真素材，不是合成信号）**：

| 样本 | 13 段去均值包络差 RMS |
|---|---|
| 同一份 DI 过两个【真预设】（两文件直接差 1.56 dB）各铺 6 段拼成一首歌 | 逐段 0.75~0.82，**中位 0.78** |
| 真·单音色的 BlackShout（全曲） | 中位 **0.84**，p90 1.42，最大 5.16 |
| 同一音色内不同段落（180-200 vs 200-220） | **2.5 dB** |
| 鼓单独 / 贝斯单独 / 20 秒数字静音 | 4.53 / 6.09 / **3.44 dB** |

**两种音色的歌，每个统计量都比一种音色的歌更「一致」** —— 判据与信号方向相反。

**机理**：段偏差测的是「段 vs 全曲均值」。换音色的段占 f 时，那簇的偏差只有 (1−f)·D；
50/50 时 1.56 dB 被折半成 0.78。而单音色歌的内容起伏本来就在 0.84~2.5。
内容空间与音色空间**完全重叠**，所以这不是阈值调不调的问题。

**还活着的那一半**（这一半是对的，别一起砍掉）：
· 每段打印**电平** + 一行「20 秒数字静音 = 3.44 dB」的存在性参考 —— 因为吉他不在时这个数不再代表吉他；
· 用**可行动空间 0.62 dB 当单位**问「把最异常那段剔掉，目标动多少」：实测剔掉前奏只动 **0.09 dB（最大 0.22）**
  -> 远小于可行动空间 -> **这段不重要，不用问用户**；
· `--drop=a-b` 是唯一改变行为的东西（用户答了要用哪一段，代码得有个地方接）。

**失效条件**：反例的夹具是「同一 DI 过两真预设再拼接」（内容受控），所以它证明的是「内容受控时这个量也测不出音色差」；
【疑似】若两簇音色差 ≥3.2 dB（判据 A 在 50/50 下的门槛），判据 A 会响 —— 但那已大于本项目实测过的任何一次预设更换。
