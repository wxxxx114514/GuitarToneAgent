## 7. 奏法处理

### 7.1 闷音看衰减，不看频谱

| 奏法 | 判据 | 改频谱吗 |
|---|---|---|
| **闷音** | **音符衰减**：手掌压弦 100–250 ms 就死，开放弹响 1 s 以上 | 也改（高频砍、低频厚），但**频谱量不能当判据** |
| **泛音**（自然/人工） | 基频被抑制 | ✅ 大改 |
| **力度** | — | ❌ 不改频谱（实测 12 dB 输入只改 0.3–0.44 dB） |
| 推弦/滑音/揉弦/点弦/扫弦 | — | ❌ 不改（纯音高域或瞬态） |

**为什么频谱量不能当判据**：`低频段(100–450Hz)占比 + 频谱质心` 测的是**音区高低**和
**混音 EQ** —— 弹得低占比自然就高，混音砍了低频占比就低。闷音与否它看不见。
翻车细节见 `07-已证伪路线.md` §8.5。

**判据实现**：`songlib.note_decay_times()` —— 峰值后 0.4 s 窗口内拟合 dB 包络的衰减斜率（dB/s）。

**当前限制**：它在**隔离单音**上干净，在**密集分轨**上会大面积测不出来
（温度差吉他轨 p25 = 中位 = p75 全部撞上限，**贝斯轨同样饱和** ——
说明是"测不了"，不是"没闷音"）。所以 `technique.py` 必须同时报**覆盖率**；
覆盖率低就按"测不了"处理，**去问用户，不要硬给百分比**。

### 7.2 奏法不匹配 = 比对结果无效

**实测证据：**
```
全曲比对（奏法混杂）  1.23 dB  →  用户听不出差别（特征被平均掉了）
闷音比对（奏法对齐）  1.41 dB  →  暴露出 2-3 kHz 有 5 dB 的真实差距
```

**所以必须：**

1. 奏法检测：用**衰减**判闷音（判据见 §7.1），配方钉死在 `songlib.note_decay_times()`。

   **★ 所有脚本调同一个实现。** 文档里的数字会因为重新实现而漂移，代码不会。

**（顺带，别搞混）内容匹配用的描述子是另一套**：`低频占比（100–450Hz）+ 频谱质心`，
描述的是**音区 / 明亮度**，配方同样钉死在 `songlib.technique_descriptor()`。
**它不能判奏法**（原因见 §7.1）：

   ```python
   DESC_RECIPE = {
       # ---- 聚合顺序 ★★★ 最大的一格（实测同输入差 11 点）----
       "aggregation": "per_frame_then_stat",
       #   "per_frame_then_stat"  逐帧算比值/质心，再跨帧统计
       #   "pool_then_ratio"      先池化频谱，再从池化谱算比值/质心

       # ---- 域（两种聚合下语义不同，故拆两格）----
       "per_frame_domain": "power",     # per_frame 下："power" | "amplitude"
       "pooled_domain": "power",        # pool 下：
       #   "power"          池化 |X|^2 再算比值           -> 86.0%
       #   "amplitude"      池化 |X|   再算比值           -> 66.3%
       #   "rms_amplitude"  池化 |X|^2 后【逐 bin 开方】  -> 61.6%   ★ 别混

       # ---- 跨帧统计（仅 per_frame 有效）----
       "frame_statistic": "median",     # "median" | "mean"

       # ---- 时频 ----
       "n_fft": 8192,  "hop": 4096,  "window": "hann",  "gate_db": -60.0,

       # ---- 频段与分母 ----
       "band_lo": 100.0,  "band_hi": 450.0,
       "denominator_hi_hz": None,      # None = 到 Nyquist
       #   ⚠️ 「分母上限无影响」只对【干声】成立（6k 以上没能量）。
       #      失真湿声在 10k 以上有大量谐波 —— 用湿声测时必须重新确认。

       "recipe_version": "2026-09-28/b",
   }

   低频占比 = 100 × sum(V[100:450]) / sum(V[全谱])   V 由 aggregation/domain 决定
   频谱质心 = sum(f·V) / sum(V)                      同上
   ```

   **整组变体的谱系**（同一份 di.wav，由 recipe_version=2026-09-28/b 复现）：
   ```
   A pool + rms幅度        61.6% / 652 Hz
   C pool + 平均幅度       66.3% / 582 Hz
   G 逐帧 + 幅度 + mean    73.3% / 511 Hz
   F 逐帧 + 幅度 + median  75.8% / 467 Hz
   B pool + 平均功率       86.0% / 307 Hz
   E 逐帧 + 功率 + mean    90.9% / 298 Hz
   D 逐帧 + 功率 + median  97.1% / 325 Hz   ← 本配方
                          跨度 35.5 点
   ```

   **各格权重（di.wav，只改一处）：**

   ```
   聚合顺序（per_frame vs pool）   功率域内差 11 点      ← 最大 ★
   域（功率 / 幅度 / RMS幅度）     ~20~25 点，质心 2 倍
   统计量（median / mean）         6~8 点
   门限（有 / 无）                 3~4 点
   窗长 2048~16384                 ~1 点
   hop                             0
   分母上限 6k~24k                 0（★ 仅对干声成立）
   ```

   > **一个阈值取决于实现的守卫，不是守卫。**
   >
   > **引用规矩：本文档里的描述子数值，只有带 `recipe_version` 的才可引用；**
   > **其余裸百分数（含早先所有版本）一律「来历不明，勿引用」。**
   > 所以：**配方写进代码，不写进文档；文档只负责指向代码。**

   **锚点（必须挂在实现版本上，不能是裸的百分数）：**

   ```
   由 songlib.technique_descriptor() 于 recipe_version=2026-09-28/b 测得
   （样本：某首歌的吉他轨，湿声）

  低频占比 中位 37.5%      质心 中位 1388 Hz
   ```

   > **⚠️ 阈值也是锚点的一部分。** 换实现（改聚合顺序、改域、改统计量）
   > 这些数会一起漂 —— **必须整组重新标定，不能只改一半。**
   >
   > 旧文档里的裸数字（闷音 28.8% / 1621 Hz）**已作废**：说不清是哪个实现量的。
   > 新锚点带实现版本号，可追溯。

   > **⚠️⚠️ 绝对锚点【只用于湿声】；干声一律【自参照】。**
   >
   > 干湿不可横向比（失真堆谐波、混音又高通）。
   > 本节锚点全是在【吉他轨（湿声）】上量的；干声是另一个量级：
   > ```
   > 由 recipe_version=2026-09-28/b 测得：
   >   用户真实录音（干声）   88.6–97.1% / 262–325 Hz
   >   合成 DI（干声）         6.4% / 2924 Hz
   > ```
   > **这些数不能当干声的绝对闸门。**
   >
> `verify_di.py` 的奏法检查也是**自参照**设计
> （用户的闷音段 vs 用户自己的开放段，只比差值不看绝对值），
> 而且**只在参考曲确实有两种以上奏法时才跑**。后人不要改成绝对阈值。

2. **不确定就问用户**——「这段是闷音还是开放？」（一句话 5 秒，猜错一轮 5 分钟）

3. **可比性守卫**：描述子不匹配时**拒绝出结果**，不要给一个偏大的误差
   （那会被误当成「音色还没调好」）

### 7.3 【内容匹配】—— 今天最重要的方法论 ⭐

**比对要成立，DI 的内容必须跟目标的内容同分布。三个维度：**

| 维度 | 不匹配的后果 | 怎么匹配 |
|---|---|---|
| **奏法** | 闷音 vs 开放，低频段占比差 2.5 倍 | §7.1 的描述子测出参考曲的奏法比例 |
| **调性** | 基频不同 → 13 个频段错位 | 从参考曲测调性（chroma），DI 用同一个调 |
| **和声** | 弹的和弦不是参考曲的和弦 | 和弦模板匹配，找出主要和弦 |

#### 实测代价（同一个预设 EQFIX2，同一个全曲目标）

```
DI 内容                              对目标的偏差
开放音阶 + C 和弦（不匹配）           3.87 dB
E/B 强力和弦闷音（匹配）              1.60 dB
                                     ────────
                                     2.27 dB 全是内容差异
```

**换句话说：内容不匹配时，测出来的"音色误差"里有 60% 是假的。**

#### 调性差多少算差

```
F# 调 DI  vs  E 调 DI（同样的奏法、同样的和声结构）
→ 包络差 RMS 0.78 dB，95 Hz 处最大 2.36 dB

对比：可行动空间 0.62 dB
```

**所以调性必须匹配。** 隔一个半音就会引入跟可行动空间同量级的偏置。

### 7.4 目标曲线：用全曲，不要只用闷音段

**早先的做法**是"只挑跟参考窗口形状接近的段落"（形状距离 < 2.0 dB）。**这会导致过拟合**——目标只代表闷音，调出来的预设也只对闷音好。

**实测：全曲吉他轨的段间一致性**（2026-10 用真工具重跑，`target_whole.py`）

```
每 20 秒一段，与全曲平均的 13 段包络偏差（去均值形状）：
   0-20 s    5.16 dB   ← 前奏独奏，唯一的例外
   20-240 s  0.45 ~ 1.44 dB
   中位 0.84 dB   p90 1.42 dB   共 12 段（末段只剩 5.7 秒，不足一段没计入）
   参考：20 秒【数字静音】在这个量上也有 3.44 dB（= 目标向量自身的范数）
```

**结论（可证伪的措辞）：除前奏那一段，其余段落在 1.5 dB 以内 —— 用全曲当目标没有引入新的偏置。**

> **★ 但这个数【不能用来判断「这首歌是不是有两种音色」】—— 已实测证伪，别再提这个判据：**
> 同一份 DI 过两个**真预设**（两文件直接差 **1.56 dB**）各铺 6 段 20 秒拼成一首「歌」（内容完全相同、只有音色不同）：
> 逐段只有 **0.75~0.82（中位 0.78）**，而真·单音色的 BlackShout 是 **0.84** —— **两种音色的歌反而更「一致」。**
> 机理：段偏差 = 段 vs 全曲均值，换音色的那 f 比例段其偏差只有 (1−f)·D，**把音色差折半了**；
> 而单音色歌里内容起伏本来就能到 0.84~2.5 dB（同一音色内 180-200 vs 200-220 段 = **2.5 dB**）。
> 内容（2.5~6.1）比音色（0.86~1.56）大 2~4 倍且区间**完全重叠** —— 给多少阈值都分不开。详见 `07-已证伪路线.md` §8.7。

**全曲目标 vs 闷音窗目标：RMS 0.60 dB，最大 1.14 dB**（主要在 190–537 Hz，全曲目标要**更多**低中频）。

**过拟合的教科书案例（FIX4）**：

```
              闷音 DI（训练场景）    开放音阶/C 和弦（场景外）
EQFIX2            1.41 dB              3.32 / 2.55 dB
FIX4              0.84 dB              3.87 / 3.35 dB
                 ─────────            ──────────────
                 改善 0.57 dB          变差 0.55 / 0.80 dB
```

**训练集赚 0.57，场景外亏 0.55–0.80。净负。**

### 7.5 标准 DI：怎么造一个内容匹配的干声

**优先顺序：**

1. **【主】用户按指令录** —— 定 EQ 的唯一依据（见 §9.1）
2. **【辅】合成 DI** —— **管线验证夹具，不参与音色判定**（见 §9.1）。
   理由不是「它错得多」，而是**「你无法知道它错了多少」**：
   参考曲是湿声，结构不同比不了，除了让用户再录一条没有别的验证方式。
   **推不出上界的误差不能进优化循环。**
3. ❌ **不要用随手弹的东西**——内容不匹配，测出来的数字有 60% 是假的

### 7.6 先判织体：单音型 / 强力和弦 / 和弦型 ★

**这是做任何内容对齐之前的第一个判断，而且必须自己判，不能等用户提示。**

拿和弦模板直接套单音 riff，会得到一张"看起来很像样"的和弦表——因为模板匹配
总会返回一个最大值解，**它不告诉你这个解有多烂**。整条链路从这一步开始歪。

**判据：每帧的"显著音级数"**（chroma 归一化后 ≥ 15% 总能量的 bin 个数）

| 织体 | 显著音级数 | 为什么 |
|---|---|---|
| 单音（旋律 / riff） | **1** | 基频和它的谐波全部折叠到同一个音级 |
| 强力和弦 | **2** | 根音 + 五度 |
| 三和弦 | **3+** | 根音 + 三度 + 五度 |

`chords.py` 会打印 `[织体]` 行给出平均值和分布，并把结论写进 `spec.json` 的
`texture`（`single` / `power` / `chord`）。

**⚠️ 这个判据只是【线索】，不是结论。两件事必须先说清：**

**① 阈值（1.8 / 2.4）只在【干净 DI】上试过，而且有反例。**

```
                     平均显著音级数
c#.wav   单音            1.06      <- 分得开
c#和弦.wav 和弦           1.91      <- 分得开
c.wav    单音            2.46      <- 反例！比和弦还高，还没解释清楚
```

**别拿它当判决，只当"值得看一眼"的信号。**

**② 真实用途是在【分轨后的吉他轨】上跑，而上面那组数是在干净 DI 上量的。**
在混音里判织体的真正难点是三道障碍（来自另一次实测）：

| 障碍 | 后果 |
|---|---|
| **混音高通** | 目标曲线最低频段 80–113 Hz（−11.97 dB）。吉他轨在混音里被高通过了，**"参考曲低频少"分不清是"弹得高"还是"后期砍的"** |
| **失真互调** | 失真产生 f1±f2 互调。强力和弦 (R + 1.5R) 的互调落在 0.5f 和 2.5f：用 2.5f 判"有没有三度"会被污染；反过来 R5 又会被失真填满的谐波列压低 |
| **分轨串音** | 吉他轨里 < 80 Hz 的能量可能是贝斯漏进来的（§2.3 记录过 B1 占 27%） |

> **已经排除的一条**：担心失真让单音的第 3 谐波（折到五度）把单音伪装成强力和弦 ——
> **实测不成立**。同一个单音加 tanh 失真到 20×，显著音级数 1.06 → 1.01，基本不动。
> **失真不是主要威胁，高通和串音才是。**

**③ 拿不准就按【织体未知】处理，不要硬判。** 织体未知时的正解是
**让用户照谱子弹主 riff** —— 内容就是这首歌本身，匹配度天然 100%，
根本不需要从混音里反推。见 §7.5 第 1 条。

**判出织体之后，下游三件事跟着变：**

1. **分析**：单音型不要输出"和弦进行"，改看**音高轮廓**（每个音往哪走）。
   `chords.py` 的和弦类型统计对单音型没有意义。
2. **DI 指令**：**单音段固定必录，不随织体变**（应录尽录）；和弦段按参考曲指定的和弦走。
   织体只影响"怎么分析"，不影响"录什么"——判据本身不够可靠，就不该让它决定录不录。
3. **误差敏感度**：单音型对**调性 / 音准**比和弦型敏感得多——和弦有掩盖效应，单音没有。
   隔一个半音的偏置会直接看出来。

> **别跟 §7.4 的"开放音阶"反例搞混**：那条废掉的是**奏法不匹配**
> （开放音阶 vs 目标是闷音），不是"音阶"本身。单音音阶只要**奏法对**就是有效的，
> 而且它能补上和弦补不了的音高覆盖。

### 7.7 音阶段的三条硬约束（喂给频谱的东西，错了整条链都偏）

**音阶段存在的唯一理由是补音高覆盖** —— 只弹和弦的话，频谱只被根音和五度激励。
所以这一段一旦错，喂进去的就是错音级。三条约束：

| 约束 | 为什么 |
|---|---|
| **跟调式** | 小调歌用自然大调音阶，会喂进不属于这首歌的音级。实测「Am-F-C-G」按 A 大调弹 = A B C# D E F# G#，**7 个音里 2 个是错的**。调式优先取 chords.py 写的 key_mode；spec 里没有时，di_instructions **先用带三度的和弦判**（只要有一个三度和弦就是真证据），**全是强力和弦（X5）时才按金属/摇滚的先验取自然小调并告警**|
| **不准闷音** | 闷音音符 100–250 ms 就死了，**测到的是起音瞬态、不是音高** —— 恰好废掉这一段唯一的用处。单音段必须放开弹（响 1 s 以上） |
| **指法要连贯** | 「音对」不够，还得**是人弹的**。为换一个和弦让整只手横移 5 品，用户弹不对，录出来的东西也就不代表这首歌 |

**第二条和「应录尽录」不冲突**：段落**有没有**这一段（固定必录），和这一段**用什么奏法弹**，是两件事。
必录 ≠ 闷着弹。
