# 电吉他效果器调音 Agent

> 用真实硬件（MOOER GE250）做**音色复制**与**人机交互调音**。
> 闭环：**参考音频 → 目标指纹 → 改预设 → reamp 测量 → 误差 → 解参数 → 循环**

## 什么时候用

要复刻某首歌的吉他音色，或要在 GE250 上调音色时。**接触设备、改预设、做 reamp 之前先读这份。**

## 五条铁律

1. **内容不匹配的比对是无效的。**
   DI 的奏法 / 调性 / 和声 / 调弦必须跟目标一致。不对齐时测出的「音色误差」里 **60% 是假的**。
   详见 `reference/06-奏法处理.md`

2. **收敛看【单轮增益塌缩】，不看绝对阈值。**
   每个演奏者、每首歌的地板都不一样。先量地板，再看单轮增益（< 0.1 dB 即榨干）。
   详见 `reference/05-指标体系.md` · `reference/08-工作流详解.md`

3. **预期与实际严重不符时，第一嫌疑是「预设没加载」，不是设备非线性。**
   加载后**让用户回读屏幕上的预设名**。预设命名用递增序号，不要靠词序区分。

4. **起点预设【从规格组】，不从现成预设里挑。**
   同一个预设的残差只在**它自己那首歌**里有意义，跨歌不可比 —— 拿"A 歌上 1.77 dB 的那个预设"
   直接去做 B 歌 = 抄别人的答案。**而"抄"这条路根本不许开**：起点由参数表 + 经典配置表组出来，
   每个值要么是说明书默认值、要么是经典配置（推子的 Gain/Level/Tone）。
   **顺序永远是：先定当前歌的曲风 → 按 §10.7.3 定箱头家族/箱体/推子 → 各测一次比预测残差。**
   详见 `reference/08-工作流详解.md` §9.0.5

5. **一个判据，只有在能说出「我在什么条件下会失效」时才准用。**
   没有适用条件、没有置信度、没有交叉验证的判据 = 把猜测当事实往下传。
   **实测教训**：`guitar.wav` 的 L/R 相关只有 **0.3325**（L=主音 / R=节奏，两把琴），
   `x.mean(1)` 静默平均 → **目标曲线从第一秒起就是错的**，全程无人报错。
   调弦 / 奏法 / 织体三个判据也是同一个病。
   > **唯一带自检的环节（目标曲线的分段一致性），恰恰是唯一没出错的环节。**

### 开工前（每次，不是出问题时）

**先读 `reference/04-测量协议.md` 和 `reference/03-陷阱清单.md`。**

理由：陷阱大多是「读的时候觉得对，踩完了才知道错」—— 按症状查是来不及的。

## 工作流

```
⓪ 第一次用某台设备：向用户要说明书的【模块表 + 参数表】，agent 照模板自己填
   （GE250 也一样 —— 从预设文件里反推不出参数表）
   模板 reference\parameter_table.template.json → devices\<型号>\parameter_table.json
   填完必须过校验，不通过不许往下走：
     tone.bat run check_parameter_table.py devices\<型号>\parameter_table.json
   要哪些字段、缺了怎么办：reference\13-两表规范.md
① 确认当前是哪首歌（每次新对话的第一件事）
② 分析参考曲 → 目标曲线 + 调性/和弦/调弦/奏法 + ★曲风
③ 定起点预设（★ 从规格组：曲风 → §10.7.3 经典配置 → 型号按名字匹配参数表 → 值取说明书默认值）
   生成录音指令（给用户）+ 设备操作单（箱头/箱体/推子）
④ ★ 用户录 DI + 设好效果器
⑤ 验证干声（不合格就回到 ③ 重新指导）
⑥ 归一化 → 发送
⑦ ★ 用户加载预设（回读确认）
⑧ ★ 交付前跑 `tone.bat run tools/check_all.py`（全部脚本编译 + 两个回归套件）—— **失败不许交付**
⑧ reamp 测量 → 哨兵检查 → 最小二乘解 EQ
⑨ 单轮增益 < 0.1 dB ? 结束 : 生成新预设回到 ⑦
```

**每轮两处需要人：④ 和 ⑦。工具入口 `tone.bat`（list / new / run / env）。**

## 自己判断，不要等用户提示

**这几件事每次都要主动做。等用户开口才做，就是漏了一步。**

| 要判断的 | 怎么判 | 漏了的后果 |
|---|---|---|
| **织体：单音型 / 强力和弦 / 和弦型** | `chords.py` 的 `[织体]` 行 —— **只是线索**；判不出来就让用户照谱子弹主 riff | 拿和弦模板去套单音 riff，**和弦全是错的**，后面全歪 |
| **调弦** | ★ **问用户**（它是【输入】不是分析：实测低音带被贝斯压低 28 dB，音频里几乎测不准）；用户没说就按默认标准 | 拿音频去推 —— 推错了整段指法作废 |
| **奏法占比** | `technique.py`（**音符衰减**）；**测不出来就问用户，不要假设闷音** | DI 跟参考内容对不上，误差 60% 是假的 |

**共同点：这三件都能从音频里算出来。能算的就去算，不要去问用户。**
判据和下游影响见 `reference/06-奏法处理.md` §7.6。

**反过来：只有【算不出来】的事才问用户** —— 比如他用的是哪把琴、有没有开推子。

## 一句话

> **比对要成立，内容和目标必须先对齐。**
> **每次测量前验证发送信号与削顶；小步迭代；误差分地板和可行动；**
> **指标判方向，哨兵判跑偏；调参数用最小二乘解（频段会重叠）。**

> **能力上限：`reference/00-边界.md` —— 真箱 + 麦克风实录的那几截，模拟抓不到也调不掉。**
> **撞上就该停，不是继续调。什么时候算撞上，见 `reference/09-参数速查与经典配置.md` §10.7.6。**
