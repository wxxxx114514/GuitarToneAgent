## 4. 测量协议

### 4.1 分层测量（必须）

| 层 | 测什么 | 预设要求 |
|---|---|---|
| **核心音色** | 频谱包络、谐波结构、动态压缩、增益 | **关掉 REVERB / DELAY** |
| **周边** | RT60、延迟时间、混音比 | 单独测，用**孤立脉冲** |

**为什么必须分层**：混响对**谐波测量**的污染可达 3.65–8 dB。

**对「时均频谱包络」的污染：0.5–1.1 dB**（两个会话、两首歌、不同混响设置各测一次：
0.47 dB / 0.90–1.02 dB）—— **比谐波层小一个量级，测包络时可以忽略。**

> **量级结论稳定，绝对数值随混响设置变。** 换歌/换 reverb 参数时按 1 dB 量级估，
> **不要当标定值引用。**

> **⚠️ "周边"这一层可能根本测不到参考端的真值** —— 见 §3.16。
> 分轨会把混响尾巴掐成精确全零（§3.15），母带上的干净衰减又常常不存在。
> **没有真值时：只标定器件端 + 选一个合理的值，并写清楚"这一层是选的，不是测出来的"。**

### 4.2 测混响要用孤立脉冲

音乐信号测不出 RT60（音符本身的衰减和混响混在一起）。
**发一个短脉冲 + 长静音**，直接从冲激响应里读：
```
0.5s 静音 → 10ms 带限脉冲(1-8k) → 5s 静音
```

**★ 重复性判据：连测 4 次，极差应 < 0.02 s。**

实测（REVERB Decay=30）：**0.47 / 0.47 / 0.46 / 0.47 s**，极差 0.01 s —— 这个量级才算测住了。
**极差大于 0.05 s 说明没测准**（脉冲被截、混响没跑完、或环境噪声），重测。

**衰减不是单一指数**：实测 0.05–0.15 s 段 154 dB/s，0.30–0.50 s 段降到 80 dB/s
（扩散尾）。**报 RT60 要说明取的是哪一段。**

**⚠️ 脉冲电平必须跟发送信号共用同一个归一化目标（−32 dBFS）。**
整条链实测增益 **+32 dB**（见 §1.3 / §10.6），
**−6 dBFS 的脉冲必然削顶**——那样测的是削顶后的冲激响应，不是器件的。

### 4.3 电平选择

送出去的电平决定放大器的工作点（实测 5:1 压缩）。
- 高增益预设：**−30 ~ −35 dBFS 峰值**（避免输出削波）
- 先跑一次空音色标定固定增益，再按需要衰减

**为了保护耳朵**：默认 `DI_GAIN = -14 dB`；正式测量前先发 1 秒低电平探针让用户确认音量。

### 4.4 对齐

每次测量都要重新对齐（往返延迟会变，实测 **100–250 ms**）。
互相关搜索范围取 **±300 ms**——必须覆盖往返延迟的上界。

**⚠️ 窗口开小了会误判"回环断开"**（实测事故）：
搜索范围 ±60 ms 时，最佳 lag 落在 **+49.44 ms**（正好是窗口边界），
相关系数掉到 **0.002**，差点判定设备坏了。
**设备正常时相关系数应在 0.6 左右**（实测 0.619 / 0.654）。

> **诊断判据：lag 出现在搜索窗口的边界上 = 窗口开小了，不是设备有问题。**

**对齐 lag 本身就是诊断量**——见 §6.4。

### 4.5 噪声审计（每首歌开工时做一次）

**链路每一环都量一次静音段**（`noise_audit.py`）：

```
① 用户录的 DI        信噪比应 > 40 dB
② 湿声录音          应 > 80 dB（设备有噪声门，实测 82–86 dB）
③ 分离后的吉他轨     比较两个模型在"吉他静音段"的残余
                     —— 差值就是泄漏量（实测 BS-Roformer 比 htdemucs 干净 63 dB）
④ 合成 DI（如果用了） 应该是完美数字静音（−240 dBFS），不是的话生成器有问题
```

**⚠️ 工频必须在【静音段】里量。**
在音乐段落里量会撞上音符——**实测：120 Hz 的测量撞上了 B2（123.5 Hz），得出假结论。**

**实测基线**（可作参考）：
```
用户录的 DI（开放演奏）   SNR 64.8 dB   工频 50Hz 相对信号 −52 dB
湿声录音                  SNR 83.5 dB   （设备噪声门）
BS-Roformer 吉他轨        −240 dBFS（数字静音）
htdemucs 吉他轨            −42.5 dBFS  ← 吉他静音段仍有残余 = 泄漏
```
