### 2.1 核心脚本（全部 song-agnostic）

**所有脚本通过 `SONG_DIR` 定位数据**，不硬编码任何一首歌。共用逻辑在 `songlib.py`。

| 脚本 | 作用 |
|---|---|
| **`songlib.py`** | **共用：歌曲目录解析、13 频段定义、包络计算、音频读取** |
| **`new_song.py`** | **新建歌曲工作目录 + notes.md 模板** |
| **`target_whole.py`** | **全曲目标曲线 → `<歌曲目录>/target.npy`** |
| **`chords.py`** | **调性 + 和弦（按乐句 chroma + 模板匹配）** |
| **`check_tuning.py`** | **调弦检测/设置（standard / drop_d / half_down / drop_c）** |
| **`bass_roots.py`** | **从贝斯轨提取根音（逐帧 f0 + 帧数加权，★ 别用时长短加权）** |
| **`technique.py`** | **奏法占比（低频段占比 + 频谱重心）** |
| **`di_instructions.py`** | **生成给小白看的录音指令（弦号 + 品数 + 调弦，无乐理词汇）** |
| **`gen_palm_di.py`** | **合成 DI（仅供参考，权重低，不作为定 EQ 的依据）** |
| **`verify_di.py`** | **验证用户录的 DI（电平/调性/调弦/奏法）★ 奏法是自参照的** |
| **`meas_prep.py`** | **DI → 设备格式 + 自动归一化 + 自验证** |
| **`analyze_round.py`** | **一轮湿声 vs 目标（逐频段 + 分根音）** |
| **`verify_round.py`** | **三层验证：绝对误差 / 逐帧指标 / EQ 标定** |
| `winmm.cs` | C# WinMM 封装。`ListIn()` `ListOut()` `Duplex(...)` |
| `reamp2.ps1` | 播放 + 录音（env: `SEND_FILE REC_SECS OUT_WAV`） |
| `spec_metrics.py` | 逐帧指标：LSD / LogMelMSE / MCD / SC / MultiRes + 对齐 |
| `weighting.py` / `perceptual.py` / `error_decompose.py` | 频段权重 / 感知度量 / 误差分解 |
| `noise_audit.py` | 噪声审计（链路每一环的信噪比 + 工频；见 §4.5） |
| `dl_resume.py` | 断点续传下载器（大文件必用，见 §11.2） |
| **`dl_models.py`** | **分轨模型下载 + sha256 校验（`--check` 只校验）** |
| **`setup.ps1`** | **一键装环境：uv sync + 下模型 + 自检** |

**入口**：`tone.bat`（`list` / `new` / `run`）

**参数形状**：`tone.bat run <脚本> [歌曲目录] [文件/选项]`。脚本按
`显式目录 > $env:SONG_DIR > argv[1]（必须真是目录）> --song=<目录>` 找歌；
所以 `analyze_round.py wet.wav`（配 SONG_DIR）和 `analyze_round.py songs\歌名 wet.wav` 都对。


### 2.2 预设文件格式（⚠️ 极其挑剔）

**真实位置**：
```
<GE250 预设目录>\
```

**沙箱通常不允许写这个目录**（`EPERM`），需要用户手动复制，或申请写权限。

**必须逐字节匹配的格式**（见 §3.3）：

```python
def ser(v, indent):
    pad = " " * indent; pad2 = " " * (indent + 4)
    if v is None: return "null"
    if isinstance(v, bool): return "true" if v else "false"
    if isinstance(v, (int, float)): return str(v)
    if isinstance(v, str): return json.dumps(v, ensure_ascii=False)
    if isinstance(v, list):
        if not v: return "[\n" + pad + "]"
        return "[\n" + ",\n".join(pad2 + ser(x, indent+4) for x in v) + "\n" + pad + "]"
    if isinstance(v, dict):
        if not v: return "{\n" + pad + "}"        # 空对象要展开！
        return "{\n" + ",\n".join(pad2 + json.dumps(k) + ": " + ser(x, indent+4)
                                  for k, x in v.items()) + "\n" + pad + "}"
# 输出时末尾必须加一个 \n
# 无 BOM，LF 换行，4 空格缩进
```

### 2.3 分轨（stem separation）—— 目标曲线的来源

**目标曲线来自分轨后的吉他轨，所以分轨质量是整条链路的前置条件。**

#### 为什么必须分轨

不分离（直接拿全混音当目标）的代价：

```
全混音 vs 吉他轨 的形状差       2.17 dB
我们全部可行动空间              0.62 dB
                              ────────
                              3.5 倍
```

**偏在哪**：全混音在 2–4 kHz 比吉他轨低 2.5–3.9 dB，而**吉他的"拨片咬合感"正好在这个频段**。用全混音做目标 = 主动把 presence 压下去，**正好调反**。

**原因**：混音里吉他只占 **5.3%** 的能量（人声 40% / 鼓 26.5% / 贝斯 25.6%）。

#### 两个模型：时间与质量

**时间（全曲 245.68 s = 4:05）**

| 模型 | 设备 | 全曲用时 | 实时比 |
|---|---|---|---|
| `htdemucs_6s` | CPU | **98 s** | 0.40× |
| **BS-Roformer SW 6-stem** | **GPU (RTX 4060)** | **95 s** | **0.387×** |
| BS-Roformer SW 6-stem | CPU | **约 21–22 分钟** | 5.17× |

**CPU 时间怎么来的**（重要，别搞混）：
- **实测**：30 秒片段 = 155 s（含模型加载），即 **5.17× 实时**
- **推算**：245.68 s × 5.17 ≈ 1270 s ≈ **21.2 分钟**
- **旁证**：全曲跑到 5/38 块时，块速率 34–37 s/块 → 38 × 35.5 ≈ 1350 s ≈ **22.5 分钟**
- **结论：CPU 期望时间 = 21–23 分钟/首（4 分钟的歌）**

**GPU 是 8–13 倍加速，把"绝对不能用"变成"跟 htdemucs 一样快"。**

#### 质量：4 条物理判据（BS-Roformer 赢 3 条）

| 判据 | htdemucs | BS-Roformer | 差 | 谁好 |
|---|---|---|---|---|
| 吉他轨 30–70 Hz（贝斯泄漏） | −49.4 | −53.8 | **−4.4 dB** | BS-Ro |
| 吉他轨 8–16 kHz（镲片泄漏） | −59.8 | −75.5 | **−15.7 dB** | BS-Ro |
| **贝斯轨 2–8 kHz（slap 拨弦区）** | −61.8 | −43.5 | **+18.3 dB** | **BS-Ro** ★ |
| 钢琴轨 30–70 Hz（贝斯泄漏） | −52.6 | −47.6 | +5.0 dB | htdemucs |

**★ 第三条是关键**：**htdemucs 把 slap 的拨弦高频（2–8 kHz）从贝斯轨里削掉了 18 dB**，BS-Roformer 保留了。用户听感"slap 没坏"= 这个 18.3 dB。

**注意**：用**频谱包络**判这两个模型会得出"几乎一样"的错误结论（实测 0.98 vs 0.99 dB）。**必须用物理判据**——见下面的坑。

#### 目标曲线差 0.88 dB

```
46-70s 段，两个模型的吉他轨：
  95 Hz   -2.50 dB   ← 最大（BS-Roformer 低频更少 = 贝斯泄漏更少）
  RMS 0.88 dB   最大 2.50 dB

对比：可行动空间 0.62 dB  → 0.88 dB 是"会影响优化结果"的量级
```

#### 怎么跑 BS-Roformer SW（本地）

**模型不在 audio-separator 的注册表里**，必须用"运行时注册"塞进去：

```python
# load_bsr.py 的核心技巧
_orig = Separator.list_supported_model_files
def patched(self):
    d = _orig(self)
    d.setdefault("MDXC", {})["Roformer Model: BS-Roformer SW 6-stem (local)"] = {
        "filename": "BS-Rofo-SW-Fixed.ckpt",
        "scores": {},
        "stems": ["vocals","bass","drums","guitar","piano","other"],
        "download_files": ["BS-Rofo-SW-Fixed.ckpt", "BS-Rofo-SW-Fixed.yaml"],
    }
    return d
Separator.list_supported_model_files = patched
```

**为什么能行**：`download_file_if_not_exists()` 第 560 行——**文件已存在就跳过下载**。所以只要 ckpt/yaml 已经躺在 model_file_dir 里，注册表里补个条目就能加载。

**跑法**：
```powershell
$env:PATH='<包根>\_env\ffmpeg;' + $env:PATH
& '<包根>\_env\venv_gpu\Scripts\python.exe' `
  '<包根>\tools\load_bsr.py' <输入音频> <输出目录>
```

**模型来源**（GitHub 上 404，实际在 HuggingFace）：

#### ⭐ 独立工具 `<StemSep 目录>`（日常分离用这个）

项目内的 `load_bsr.py` 是研究用的。**日常分离用这个独立工具**：

```
<StemSep 目录>\
├─ drag_and_drop.bat      把音频文件拖到它上面（最省事）
├─ separate.ps1           命令行入口
├─ README.md              用法 + 9 条调试记录 + 4 条通用教训
├─ src\separate.py        逻辑（含运行时注册技巧）
```

**用法**：
```powershell

.\separate.ps1 "<音乐目录>\song.flac" -Stems guitar,bass     # 只要两轨

```

**输出默认在歌旁边**：`<歌名>_stems\` 六个 wav。

**实测速度**：30 s → 13.3 s（0.44×）｜216 s → 93 s（0.43×）｜266 s → 121 s（0.46×）

**已验证**：中文 / 方括号 / 空格的文件名都能处理（见 §3.14）。

**临时目录可用 `STEMSEP_TMP` 环境变量覆盖**（沙箱环境下需要）。

#### 依赖坑（GPU venv 搭建）

`uv pip install audio-separator` **不会自动装全依赖**。缺了要在报错时逐个补：

```

```

**`diffq` 需要编译，会撞 uv 缓存的权限错误 → 不要装**（它只用于模型压缩，推理不需要）。

#### ⚠️ 分离质量的判据：**不要用频谱包络**

**踩过的坑**：我最初用"吉他轨的频谱包络"评判两个模型，得出"几乎一样（0.98 vs 0.99 dB）"，据此否决了 BS-Roformer。

**错在哪**：频谱包络测的是"整体频率分布"，**测不出"内容纯度"**（吉他轨里混进了多少别的东西）。而用户一耳朵就听出 slap 变好了。

**正确的判据（都是物理判据，不会骗人）**：

| 判据 | 方法 | 原理 |
|---|---|---|
| **贝斯泄漏** | 吉他轨 30–70 Hz 与贝斯轨的相关 + 电平差 | **吉他最低音 E2 = 82.4 Hz，30–70 Hz 不可能是吉他** |
| **镲片泄漏** | 吉他轨 8–16 kHz 的电平 | 吉他泛音到不了那么高 |
| **乐器缺失** | 该乐器的主频段能量够不够 | 反向检查"该给的有没有给" |
| **合成器泄漏** | 吉他不响的帧里，吉他轨的残余 | 那时候的能量只可能是漏的 |

**且测相关性时要注意**：贝斯和吉他跟鼓是同步的，**节奏本身会造成互相关**。要在"吉他没在弹"的帧里测，才能排除节奏混淆。


---


#### ★ 分轨质量自检（加总还原度）—— 每首歌做一次，很快

**判据**：六轨相加，跟原曲逐频段比相关；再查轨间相关。

```
六轨相加 vs 原曲    60Hz–12kHz 各频段相关  应 0.99+
轨间相关            吉他 vs 贝斯 / 鼓 等    应 ≈ 0
```

**为什么这条比 §2.3 上面的泄漏判据更好用**：
- 泄漏判据要知道「吉他弹不到哪个音」才能判（有乐理门槛）
- 加总还原度只看数字，**0.99 就是干净，0.8 就是模型在瞎分**

**实测（BS-Roformer SW 6-stem）**：0.99+，轨间 ≈ 0 ✓
