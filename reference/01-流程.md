
　★ 顺带还能发现：分轨质量差 / 串了别的乐器 / 根本不是纯吉他。

　而且**不许我用滑窗 / 相关去替他挑**（本轮犯过：假匹配 0.939，账本 **#11**）。

### ★ 步 4 的性质：它是「用」，不是「测」

```
一次性（A 组 H11）已经给出判据：
  · 指纹        相邻帧跳变中位：延迟 0.84（台阶） / 混响 0.50（平滑）
  · ac@500ms    延迟 +0.28  /  干·混响 −0.12      <- 「有没有延迟」的强判据
  · 回声间隔 ≈ Time 值 · 回声比直达低 22.5 dB · RT60 ≈ 1.15 s

步 4 每首歌要回答的只有两件事：① 有没有　② 是哪个

本轮的实际处置：参考曲那段【判不了】（分轨被门控清理、目标段只有 0.02 s 留白）
  -> Bypass + N/A，并用【试开 vs 试关 + 用户听】兜底
  （用户拍板：不做 —— 延迟真上来了混响也听不见）

★ 判不了 ≠ 方法无效 —— 那是【素材】的问题，见 05-已证伪路线（两条路要分开读）

★ **「判」要早 · 「开」要最后**（设计 SOP 原文：「**混响放最后**」）：
　步 4 只判（早判 —— 时基未锁不许解 EQ）；**真正打开 DELAY/REVERB 是最后一步（步 9b）**，
　开完不再解 EQ（混响会盖住干声、也会污染 EQ 判读 3.65~8 dB）。
```

### 一轮的完整动作

```
① 我读上一轮湿声 -> 检查事故(步1) + 等用户回读确认(步2)
② 我按顺序【算】这一轮所有改动：
     电平(3) -> 时间维(4) -> 窄度(5) -> 宽带(6) -> 压缩(6b) -> 窄坑(7) -> EQ(8) -> 底噪(9)
     ★ 全部算完 -> 合并成【一个】新预设
③ 用户【加载一次】          <- ★ 每轮只加载 1 次
④ 我 reamp -> 得湿声 -> 算残差
⑤ 没收敛 -> 下一轮
```

### ★★ 顺序铁律（都是【计算顺序】，不是操作顺序）

```
1 最前    = 先检查上轮湿声有没有削顶/断（有就不算了）
2 是门    = 确认设备上真是这个预设（无回读通道就用户确认）
4 在 8 前 = 算的时候先解时间维，再解 EQ（时基未锁不许解 EQ，混响污染 3.65~8 dB）
7 在 8 前 = 算的时候先解窄坑，再解 EQ（先窄后宽：反着只能修 52%，正着 99%）
★ 4 判早 · 4 开最后 = 步 4 只【判】有没有；真正【开】DELAY/REVERB 放到最后（步 9 之后、步 10 之前 = 步 9b）
```
