### 3.1 编号体系换过三次

### 3.2 步骤级改动（加 / 删 / 挪 / 改名）

| 改动 | 因为 | 依据 |
|---|---|---|
| **新增 步 6b（压缩）**，位置 = 步 6 后 / 步 8 前；判据 = 短时动态 P95−P50 + crest | 压缩整块**本来没想清**：FXA 换压缩后流程里没有「调压缩」的步骤，判据也没有 | #77 · fixes #52 |
| **步 7 的执行器改**：滤波被否 -> 只剩「换箱头/箱体（离散）」或 EQ 硬凑 | 「一般不考虑滤波效果」 | #32 · fixes #16 #52 |
| **DELAY / REVERB 从流程里拿掉**（不判定 / 不要参数 / 不进步骤） | 参考曲上判不了；且「有没有」要等试开试关 | #51 |

| **时间维重开**（原来我直接判了 N/A） | ★★★ 原方案是**分开录音**，我没做 | #135 |
| **时间维改成「只开一个模块、只动开关」** | 我做成「整条链 + DELAY」，还顺手改了参数 | #136 #137 |

| **H6 升级成 B 组 10 步** | 跑通一次不够，要**每首歌一轮一轮** | #117 #119 |

### 3.3 判据级改动

| 判据 | 设计值 | 改成 | 因为 |
|---|---|---|---|
| **H7 重复性** | σ >= 0.022 dB -> 停 | **σ < 0.1 dB**（= 精度 0.3 的 1/3）| ★ 0.022 是**我编的**，没有实测/换算依据（#119）|
| **停手** | 单轮增益 < ε（ε 由 σ 反算）| **离地板 ~0.05 dB** | 实测发现「地板 = 内容差」，追不到 0（#239 #256）|
| **削顶** | 分级：峰值 >= −0.1 报警 · 占比 > 0.1% 判死 | **唯一定义：abs(x) >= 0.999 且连续 >= 3 样本** | 项目里**四套标准**并存（#64 #65 #87）|
| **Mst** | 「呈线性幅度特征」 | ✗ **判据不成立**（局部斜率翻倍）-> **改查表插值** | #142 |
| **内容匹配** | 「13 段绝对差」 | **形状相关（去均值 13 段的 Pearson）**：>0.7 同段 / 0.4~0.7 可用 / <0.4 重录 | #111 |
| **窄坑「不重要」** | 窄度阈值 2.5 dB（我定） | **平滑前后 WMAE 差 < 0.5 dB** | #185 #187（实测 0.43）|
| **EQ 单次改动上限** | clip(Δθ, −20, +20)（不分执行器）| **按执行器区分**：EQ <= 10 dB · AMP ±40 单位 | #175 |
| **步长公式** | δ = ceil(K_SNR · σ / S_local)，K_SNR >= 10 | ✗ **未采用** | K_SNR 无出处（新SOP §6 ⛔）|

### 3.4 执行器级改动（最重要的一次）

```
设计：FXA = 「参量带」（Position / Q / Peak）-> 用来【修窄】（单段 / 1-2 段）
      H3 的目的 = 测「Q 可达上限能否到 ~3」
      —— 结论「窄凹陷可用 FXA 连续修（99%）」是【仿真】，却被当成实测引用

实测：FXA = YELLOW COMP 【压缩器】，真实参数 = Thres / Ratio / Attack / Level
      -> 「Q 可达上限」这个问题**不存在**
      -> 「窄凹陷可连续修」**作废**
      -> H3 的标定内容整体换成「四参数 -> 短时动态 / crest」
```

依据：#32（我选了 Q-FILTER，用户否）· #33（我漏了 FXA 可放压缩）· #82 · #86 · #170（核对表里写明为何不用权威的 Position/Q/Peak）· 新SOP §6 ⛔。
