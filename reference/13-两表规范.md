# 13 · 两表规范（说明书 -> parameter_table.json + mapping.json）

> ★ **为什么必须有两表**：一切「写预设 / 读参数 / 换 Type」都以它为准。
> ★ **不许拿预设文件反推参数表** —— 从一份具体预设里只能抄到某一组键名，没有范围、没有默认值，
> 而且**同一个模块换个 Type，键名可能完全不同**（EQ / FXA 尤其明显）。
> ★ 工具：<包根>\tools\check_parameter_table.py（校验器）


> ★ **与设备的关系**：**换设备 = 换两表**（整套重做）；「权威顺序 · 校验思路 · 缺了怎么办 · 两个表都不能直接信」**通用**。

## 一、权威顺序（冲突时听谁的）

```
① 用户真机【导出的预设文件】（.mo）        <- 最高
② 用户设备截图
③ 设备手册
④ 我从 PDF 抽出来的
★ 实证：手册写 DISTENCE，实际字段名是 Distance（账本 #99）
★ 实证：Type 编号是 0-based（预设里 Type=6 对应手册第 7 个 · 账本 #101）
```

## 二、★★ 本轮的教训：**两个"表"都不能直接信**

| 文件 | 它是什么 | 问题 | 怎么办 |
|---|---|---|---|
| **parameter_table.json** | 我**从手册 PDF 抽的草案**（带 PDF 页码 · ask 标记 · 范围多为「待确认」）| ★ **不能当参数表用**（真值不在里面）| 真值一律以**真机预设**为准；缺失项进「未定项」|
| **mapping.json** | 手册 <-> 预设 的字段对照（**设计期**写的）| ★★ **FXA / NS GATE 两行是错的**（那时以为 FXA 是滤波参量带）| 字段名以**真机 .mo** 为准（见 07 §3.3 · 10 坑 11）|

★ **原则**：**「两表」的价值在于「把字段名与范围列全」这个动作，不在于那两个 json 文件本身。**
　真正权威的是**真机导出的预设**。

## 三、要哪些内容

### 3.1 模块表

```
每个模块要有：有哪些 Type（各带 id 与名字）· 参数顺序 · 开关字段 · Type 字段
★ 同一模块不同 Type -> 参数可能不同（要分别列）
   —— 实证：FXA 换个 Type 就可能是「压缩」或「调制」，键名完全不同（账本 #33）
```

### 3.2 参数表

```
每个参数要有：字段名 · 范围（或枚举）· 默认值（有则填）· 单位（有则填）
★ 43 个参数（本轮 GE250）
★ 范围事实：除 EQ 5 段增益外都是 0~100；EQ 段 0~64 = ±16 dB（dB = (值−32) x 0.5）
```

### 3.3 枚举

```
例：CAB.Tube = OFF/EL34/EL84/6L6/6V6 · CAB.Mic = SM57/U47/U87/NT1/MD421/MD441/MXL2001/MXL2003/C3000/C400B
    CAB.Sync = OFF/ON · DELAY.Sub D = OFF/1-4/1-4D/.../1-16T
```

## 四、怎么校验

```
python check_parameter_table.py <parameter_table.json>           校验（不通过 exit 2）
python check_parameter_table.py <parameter_table.json> --table   校验并打印「设备规格表」给人看
★ 校验的意义：规格表是【生成器】唯一的形状来源 ——
   表里少一个字段，生成器就吐不出结构完整的预设，或者悄悄用一个没依据的值
★ 但 校验只能查「结构齐不齐」，**查不出「字段名对不对」** -> 字段名必须用真机预设核对
```

---

## 五、缺了怎么办

```
① 手册没写默认值 -> 用【范围中点】兜底，并且【记进「未定项」】（不许静默选一个）
② 认不出型号 / Type -> 也要给【未定项】，不许静默挑一个
③ 用户手上没有手册 -> 用真机导出的预设核对字段名与范围（能核多少核多少）
④ 拿到的是「某一个 Type 的键名示例」-> 不等于参数表；要么补全，要么标缺
⑤ ★ 字段名与手册冲突 -> **以真机预设为准**，并在文档里标「手册此处的写法是错的」
```
