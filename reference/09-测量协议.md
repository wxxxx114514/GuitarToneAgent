# 09 · 测量协议（reamp 怎么录、怎么比）

> ★ 这份只讲**怎么把信号送进去、录回来、再公平地比**。
> ★ 报警前提：**上机第一件事确认 AUDIO MODE = REAMP**（NORMAL 模式回传收不到效果链输出）。


> ★ **与设备的关系**：对齐三铁律 · 同素材 · 九步 · 一轮动作 = **通用**；**端点名 / REAMP / 48k / 发送安全电平 / `-DevicePattern`** = **绑设备**（换设备重设）。

---

## 一、发送信号（怎么造）

```
① 源：用户弹的 **DI**（A 组标定用「第一段 DI」，B 组调音用「目标段 DI」）
② 裁掉空白（首尾留白不参与）
③ 归一化到 **-32 dBFS**（我定；在实测安全区内，信噪比好）
④ 格式：**48 kHz / 2ch / 16bit**（★ 跟设备，不是跟目标 44.1k）
⑤ 前后加静音：前 0.5 s · 后 2.0 s（后留白用于看尾巴）
```

| 信号 | 用途 | 参数（本轮）|
|---|---|---|
| sendL32.wav | A 组标定 | 用户弹的「第一段」· −32 dBFS · 14.5 s |
| sendTarget.wav | B 组调音 | 用户弹的【目标段 DI】· 裁空白后 10.05 s · −32 dBFS · 总长 12.55 s |

> ★★ **素材铁律**：**录音只录【用户弹的 DI】**；**【参考曲】永远不送进设备、不录音** —— 它只用来算目标。
> 三段东西不许混叫：【参考曲 / 目标段】只定目标与地板 · 【DI / 发送信号】送进设备 · 【湿声】设备输出。

### ★★ 术语表（严格三词，不许混用）

```
参考曲      = 这首歌本身（分轨 = 温度差\guitar.wav）
            ★ 只用来定目标 —— 永远不送进设备、不录音
目标段    = 参考曲的那一段（本轮 = 9~17s）—— 13 段 / 动态 / crest 从它来
DI        = 【用户弹的那段】（弹的就是参考曲那一段）—— 只进设备、只会被录
            本轮有两个：第一段 DI（A 组标定用）· 目标段 DI（B 组调音用）
发送信号  = DI 做成设备能吃的 wav（sendL32 / sendTarget）
湿声      = 设备输出（wet*）

★ 注意：用户录的那份 DI，文件名沿用了一个**旧名** —— **不要按文件名去理解它**；
   它实际是【用户弹的 DI】；真正的参考曲分轨是 温度差\guitar.wav。
```


**命令**（本 skill 自带脚本）
```powershell
<本项目>\.venv\Scripts\python.exe ^
  <本项目>\tools\make_send.py ^
  "<用户录的那份 DI>" sendTarget.wav
# 参数：<源> <出> [峰值dBFS]（默认 -32）
# ★ 默认【自动裁空白】（10 ms 帧 RMS · 门限 -60 dBFS）
#   要指定区间（不裁空白）：加 -32 --from <起始秒> --secs <时长>
# 源 = 用户录的那份 DI（本轮实际路径见账本 #97；技能不写死路径）
# ★ 换设备：do_reamp.ps1 要传 -DevicePattern "<新设备名片段>"（默认 MOOER）
```

## 二、送 + 录（reamp）

**命令**
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ^
  <本项目>\tools\do_reamp.ps1 ^
  -Send <发送wav> -RecSecs 14.1 -Out <录音wav>
```

**它内部做什么**（WinMM 双工）
```
① Add-Type 加载 winmm.cs
② ListIn / ListOut，自动找名字含 MOOER 的端点
   -> 找不到就报错退出（不会静默用错设备）
③ 检查发送 wav 必须是 48k/2ch/16bit（不是就拒收）
④ Duplex(播放, 录音) -> 写回一个标准 wav
⑤ 打印：设备编号 / 播放时长 / 录音时长 / 结果信息
```

★ **录音时长取「发送时长 + 1.5 s 左右」**（把尾巴收进来）。
★ **每轮只加载 1 次**：我算完这一轮全部改动 -> 合并成一个预设 -> 用户加载一次。

## 三、★★ 对齐三铁律（我错了三次）

```
① 对齐用【有辨识度段的全范围 FFT 互相关】
   —— 不能假设从 0 开始、不能用 min(len) 截断
② 估增益用【RMS 比】
   —— 逐点最小二乘在微小错位时会崩（实测给过 -28.76 dB）
③ 同一次播放/录音的不同设置版本 -> 必须用【同一个对齐偏移】
   ✗ 每个版本分别对齐 -> 相减时相位对不上（corr 0.025）
   ✓ 统一 lag          -> corr 升到 0.70
```

**三次错法的记录**：从 0 截断 -> lag 48.75 ms（错）· 逐点最小二乘估增益 -> −28.76 dB（错）· 各自对齐相减 -> corr 0.025（错）。

## 四、★★ 同素材铁律

```
★ 比「13 段」、比「短时动态」、比「残差」—— 两边必须来自【同一段素材】
★ 实证（同一预设，只换送进去的信号）：
     送「第一段」 -> 短时动态 21.56 dB
     送「目标段 DI」 -> 短时动态  0.53 dB        （差 21 dB！）
     起点+第一段 DI 13.47  vs  起点+目标段 DI 4.89
★ 目标用的是【目标段】-> 所以 B 组一切比较都只能用【目标段】的湿声
```

## 五、★ 测一个点的完整操作（九步）

```
① 我按【16-参数表达规范】写下改动 —— **内部格式是我们自己定的 JSON**（设备无关）；送出方式：① 能加载预设 -> 写文件 / 用户加载；② 只能手动调 -> 出人工表 / 用户照表拧。改动清单格式：<模块>.<参数>：<旧> -> <新>
② 我告诉用户「点哪个模块、屏幕该显示什么」（核对表）
③ 用户切预设 + 报编号
④ 我：do_reamp.ps1 -Send sendX.wav -RecSecs N -Out wetX.wav
⑤ 我：算 13 段 / 变化 / 写矩阵
⑥ 我：自检（符号 / 位置 / 与前面是否重复 / 削顶）
⑦ 我：纯追加到账本（过程量 + 判据 + 来源 + 结论）
⑧ 我：报告（先一句话结论，再六项）
⑨ 我：跑归档自检
```

**「六项」报告格式（每步做完）**
```
第 0 项 · 结论：一句话说清「是什么/怎么办」（不许用过程量淹没结论）
1 过程量：跑的命令 + 完整原始输出 + 中间量（不截断、不摘录）
2 判据 + 来源：哪条判据 · 来源是 实测/换算/我定/待定
3 结论：通过 / 不通过 / 存疑
4 异常：逐项列（削顶 / lag / corr / 未定项 / **回读不符**）
5 （若有）给你听什么：A 文件 vs B 文件 + 听什么
6 下一步打算做什么 + 为什么
```

**「五句」上机指令格式（每步开始前）**
```
① 这一步是什么（用设备上的话，不上术语）
② 为什么要做它（一句话原理）
③ 要你做什么（动作 + 回读确认）
④ 预期看到什么 / 若相反意味着什么
⑤ 这一步不做，会缺什么
```

## 六、★ 跑一轮闭环的完整操作（B 组）

```
① 读上一轮湿声 -> 步1 事故（削顶/断/爆）
② 步2 存在性（用户确认加载）
③ 步3 电平（回录峰值；工具 = 回录侧音量 / DS-OD Volume）
④ 步4 时间维（没有就 Bypass + N/A）
⑤ 步5 窄度（判「窄坑重不重要」：平滑前后 WMAE 差 < 0.5 dB 就无视）
⑥ 步6 宽带（AMP 成片映射；先剔内容差段）
⑦ 步6b 压缩（FXA；对上参考曲 P95-P50 与 crest）
⑧ 步7 窄坑（无连续手段 -> 换箱头 或 EQ 硬凑）
⑨ 步8 EQ 收尾 -> 步9 NS -> 步10 停手
★ 顺序铁律：1 最前 · 2 是门 · 4 在 8 前 · 7 在 8 前
★ 算完全部改动 -> 合并成【一个】预设 -> 用户加载一次
```

## 七、上机检查清单（每次开机照念）

```
□ AUDIO MODE = REAMP？        （不是就先切 NORMAL 再切回来）
□ 设备端点找得到？            （in/out 都含 MOOER）
□ 发送 wav 是 48k/2ch/16bit？ （不是就重造）
□ ★★ 要录 DI 吗？吉他【音量 + Tone】旋钮拧到最大？ （没开满 -> 高频少 43 dB -> 整批重录 · 见 18）
□ 发送信号和目标【同素材】？   （B 组用 sendTarget.wav）
□ 预设文件名只用 A-Za-z0-9？
□ **字段名核过真机预设了吗？**（设备库 mapping.json 的 FXA / NS GATE 两行是错的 · 见 10 坑 11）
□ 时间维要判吗？（H11 已给判据；判不了 -> Bypass + 试开试关 + 用户听；「全关」那版**不用录**，理由见 15 §5-2）
□ 这一轮要用户点哪个模块、屏幕该显示什么 —— 核对表写了吗？
□ 录完验了符号 / 位置 / 削顶吗？
□ 账本纯追加 + 跑自检了吗？
```

## 八、常见现象 → 先怀疑什么

| 现象 | 先怀疑 |
|---|---|
| 录回来 ≈ 送出（设备像没效果）| **AUDIO MODE 不是 REAMP** |
| 数据整体对不上、符号不对 | **加载错了预设**（看核对表 / 导出的预设文件）|
| 某段怎么调都不动 | 那是**内容差段**（先看源头 DI 是不是也差）|
| EQ 实测幅度小于预期 | **叠加非线性**（H4 残差 1.259）-> 要迭代 |
| 换一版湿声就对不上相位 | **没统一 lag** |
| 动态数字跳得离谱 | **跨素材比了** |
