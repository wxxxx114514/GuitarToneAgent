## 7. 奏法处理

### 7.1 只有两种奏法真正改变频谱

| 奏法 | 改频谱吗 |
|---|---|
| **闷音** | ✅ 大改（低频厚度 +、高频砍、衰减短） |
| **泛音**（自然/人工） | ✅ 大改（基频被抑制） |
| **力度** | ❌ 不改频谱（实测 12 dB 输入只改 0.3–0.44 dB） |
| 推弦/滑音/揉弦/点弦/扫弦 | ❌ 不改（纯音高域或瞬态） |

### 7.2 奏法不匹配 = 比对结果无效

**实测证据：**
```
全曲比对（奏法混杂）  1.23 dB  →  用户听不出差别（特征被平均掉了）
闷音比对（奏法对齐）  1.41 dB  →  暴露出 2-3 kHz 有 5 dB 的真实差距
```

**所以必须：**

1. 描述子检测：**低频占比（100–450Hz）+ 频谱质心** 能把闷音和开放弦分开

   **★ 配方钉死在 `songlib.technique_descriptor()`，所有脚本调同一个实现。**
   文档里的数字会因为重新实现而漂移，代码不会。

   ```python
   DESC_RECIPE = {
       # ---- 聚合顺序 ★★★ 最大的一格（实测同输入差 11 点）----
       "aggregation": "per_frame_then_stat",
       #   "per_frame_then_stat"  逐帧算比值/质心，再跨帧统计
       #   "pool_then_ratio"      先池化频谱，再从池化谱算比值/质心

       # ---- 域（两种聚合下语义不同，故拆两格）----
       "per_frame_domain": "power",     # per_frame 下："power" | "amplitude"
       "pooled_domain": "power",        # pool 下：
       #   "power"          池化 |X|^2 再算比值           -> 86.0%
       #   "amplitude"      池化 |X|   再算比值           -> 66.3%
       #   "rms_amplitude"  池化 |X|^2 后【逐 bin 开方】  -> 61.6%   ★ 别混

       # ---- 跨帧统计（仅 per_frame 有效）----
       "frame_statistic": "median",     # "median" | "mean"

       # ---- 时频 ----
       "n_fft": 8192,  "hop": 4096,  "window": "hann",  "gate_db": -60.0,

       # ---- 频段与分母 ----
       "band_lo": 100.0,  "band_hi": 450.0,
       "denominator_hi_hz": None,      # None = 到 Nyquist
       #   ⚠️ 「分母上限无影响」只对【干声】成立（6k 以上没能量）。
       #      失真湿声在 10k 以上有大量谐波 —— 用湿声测时必须重新确认。

       "recipe_version": "2026-09-28/b",
   }

   低频占比 = 100 × sum(V[100:450]) / sum(V[全谱])   V 由 aggregation/domain 决定
   频谱质心 = sum(f·V) / sum(V)                      同上
   ```

   **整组变体的谱系**（同一份 di.wav，由 recipe_version=2026-09-28/b 复现）：
   ```
   A pool + rms幅度        61.6% / 652 Hz
   C pool + 平均幅度       66.3% / 582 Hz
   G 逐帧 + 幅度 + mean    73.3% / 511 Hz
   F 逐帧 + 幅度 + median  75.8% / 467 Hz
   B pool + 平均功率       86.0% / 307 Hz
   E 逐帧 + 功率 + mean    90.9% / 298 Hz
   D 逐帧 + 功率 + median  97.1% / 325 Hz   ← 本配方
                          跨度 35.5 点
   ```

   **各格权重（di.wav，只改一处）：**

   ```
   聚合顺序（per_frame vs pool）   功率域内差 11 点      ← 最大 ★
   域（功率 / 幅度 / RMS幅度）     ~20~25 点，质心 2 倍
   统计量（median / mean）         6~8 点
   门限（有 / 无）                 3~4 点
   窗长 2048~16384                 ~1 点
   hop                             0
   分母上限 6k~24k                 0（★ 仅对干声成立）
   ```

   > **一个阈值取决于实现的守卫，不是守卫。**
   >
   > **引用规矩：本文档里的描述子数值，只有带 `recipe_version` 的才可引用；**
   > **其余裸百分数（含早先所有版本）一律「来历不明，勿引用」。**
   > 所以：**配方写进代码，不写进文档；文档只负责指向代码。**

   **锚点（必须挂在实现版本上，不能是裸的百分数）：**

   ```
   由 songlib.technique_descriptor() 于 recipe_version=2026-09-28/b 测得
   （样本：某首歌的吉他轨，湿声）

     类别    帧数     低频占比      质心
     闷音    1315     37.5%      1388 Hz
     中间     599     18.1%      1785 Hz
     开放     254     10.9%      2000 Hz

   分类阈值: 低频>22% 且 质心<1800 -> 闷音
             低频<15% 且 质心>1800 -> 开放
   ```

   > **⚠️ 阈值也是锚点的一部分。** 换实现（改聚合顺序、改域、改统计量）
   > 这些数会一起漂 —— **必须整组重新标定，不能只改一半。**
   >
   > 旧文档里的裸数字（闷音 28.8% / 1621 Hz）**已作废**：说不清是哪个实现量的。
   > 新锚点带实现版本号，可追溯。

   > **⚠️⚠️ 绝对锚点【只用于湿声】；干声一律【自参照】。**
   >
   > 干湿不可横向比（失真堆谐波、混音又高通）。
   > 本节锚点全是在【吉他轨（湿声）】上量的；干声是另一个量级：
   > ```
   > 由 recipe_version=2026-09-28/b 测得：
   >   用户真实录音（干声）   88.6–97.1% / 262–325 Hz
   >   合成 DI（干声）         6.4% / 2924 Hz
   > ```
   > **这些数不能当干声的绝对闸门。**
   >
   > `verify_di.py` 的奏法检查正是**自参照**设计
   > （用户的闷音段 vs 用户自己的开放段，只比差值不看绝对值）——
   > **那是唯一在干声上成立的判据。后人不要改成绝对阈值。**

2. **不确定就问用户**——「这段是闷音还是开放？」（一句话 5 秒，猜错一轮 5 分钟）

3. **可比性守卫**：描述子不匹配时**拒绝出结果**，不要给一个偏大的误差
   （那会被误当成「音色还没调好」）

### 7.3 【内容匹配】—— 今天最重要的方法论 ⭐

**比对要成立，DI 的内容必须跟目标的内容同分布。三个维度：**

| 维度 | 不匹配的后果 | 怎么匹配 |
|---|---|---|
| **奏法** | 闷音 vs 开放，低频段占比差 2.5 倍 | §7.1 的描述子测出参考曲的奏法比例 |
| **调性** | 基频不同 → 13 个频段错位 | 从参考曲测调性（chroma），DI 用同一个调 |
| **和声** | 弹的和弦不是参考曲的和弦 | 和弦模板匹配，找出主要和弦 |

#### 实测代价（同一个预设 EQFIX2，同一个全曲目标）

```
DI 内容                              对目标的偏差
开放音阶 + C 和弦（不匹配）           3.87 dB
E/B 强力和弦闷音（匹配）              1.60 dB
                                     ────────
                                     2.27 dB 全是内容差异
```

**换句话说：内容不匹配时，测出来的"音色误差"里有 60% 是假的。**

#### 调性差多少算差

```
F# 调 DI  vs  E 调 DI（同样的奏法、同样的和声结构）
→ 包络差 RMS 0.78 dB，95 Hz 处最大 2.36 dB

对比：可行动空间 0.62 dB
```

**所以调性必须匹配。** 隔一个半音就会引入跟可行动空间同量级的偏置。

### 7.4 目标曲线：用全曲，不要只用闷音段

**早先的做法**是"只挑跟参考窗口形状接近的段落"（形状距离 < 2.0 dB）。**这会导致过拟合**——目标只代表闷音，调出来的预设也只对闷音好。

**实测：全曲吉他轨的段间一致性**

```
每 20 秒一段，与全曲平均的偏差：
   0-20s   5.30 dB   ← 前奏独奏，唯一的例外
  20-220s  0.43 ~ 1.47 dB
  中位 0.87 dB   p90 1.45 dB
```

**结论：除了前奏，全曲音色一致，可以直接用全曲当目标。**

**全曲目标 vs 闷音窗目标：RMS 0.60 dB，最大 1.14 dB**（主要在 190–537 Hz，全曲目标要**更多**低中频）。

**过拟合的教科书案例（FIX4）**：

```
              闷音 DI（训练场景）    开放音阶/C 和弦（场景外）
EQFIX2            1.41 dB              3.32 / 2.55 dB
FIX4              0.84 dB              3.87 / 3.35 dB
                 ─────────            ──────────────
                 改善 0.57 dB          变差 0.55 / 0.80 dB
```

**训练集赚 0.57，场景外亏 0.55–0.80。净负。**

### 7.5 标准 DI：怎么造一个内容匹配的干声

**优先顺序：**

1. **【主】用户按指令录** —— 定 EQ 的唯一依据（见 §9.1）
2. **【辅】合成 DI** —— **管线验证夹具，不参与音色判定**（见 §9.1）。
   理由不是「它错得多」，而是**「你无法知道它错了多少」**：
   参考曲是湿声，结构不同比不了，除了让用户再录一条没有别的验证方式。
   **推不出上界的误差不能进优化循环。**
3. ❌ **不要用随手弹的东西**——内容不匹配，测出来的数字有 60% 是假的
